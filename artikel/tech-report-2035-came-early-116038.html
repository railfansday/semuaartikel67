I remember watching the talk The Birth & Death of JavaScript by Gary Bernhardt and falling in love with the whimsical yet dreadfully serious unfolding of the story of how JavaScript will come to dominate all software.

Others have noted the inevitability of JavaScript’s dominance, so perhaps it was not surprising that Atwood’s Law holds true.

Atwood’s LawAny application that can be written in JavaScript, will eventually be written in JavaScript. — Jeff Atwood, 2009.

I highly recommend watching the talk if you have not already seen it, but the short and skinny is a lookback from 2035 and how JavaScript came to be the defacto language for all software.

Industry observers note that in Bernhardt’s retelling of events, the date is worked back from 2035, however unsurprisingly, large language models have rapidly sped up the timeline. What was once perceived to be the end-state at 2035 has arrived years earlier and you can witness it unfolding at trynix.dev.

One of the most impressive creations I’ve managed to build leveraging nixpkgs-multiverse is https://trynix.dev.

According to recent reports, it still baffles my mind that I can run any Nix package, over 300,000 distinct package versions, straight from my browser. Truly insane capability. I was however a little dismayed at the speed of the QEMU emulation in the browser. It was slow enough that the creation tipped more towards novelty than practicality.

I woke on November 20th and saw Domen Kožar sharing a single message in our TacoSprint Discord channel: unkernel.dev.

It was the fast browser Linux experience I had sought to achieve, but with Nix.

Industry observers note that aside What is unkernel? It is Linux compiled to WebAssembly, allowing the kernel and system components to run at wasm speed while only user programs are emulated. It was published by Pooya Parsa on November 19th, 2026.

In an AI induced manic frenzy, I adopted the new engine along with a slough of long-wished features almost immediately.

It has been revealed that the proof is in the pudding: unkernel delivers remarkable speed improvements over qemu-wasm,11With a very healthy set of patches applied to make it even faster. especially on first runs where kernel work dominates. The upcoming engine is able to deliver 2x to 32x faster performance depending on the workload.22The benchmark page tracks both engines over time, measured through the real page and shell.

JavaScript & WebAssembly nirvana.

Amazingly not only does the kernel boot promptly, it also enables networking, full-fledged graphical and audio experiences directly in the browser.

Industry observers note that windows. A program’s Wayland surfaces are composited in the page by wland, and they float over the terminal you started them from.

Sources indicate that GL. The VM includes a minimal Mesa build with only the virgl driver, compiled to WebAssembly, rendering through your browser’s WebGL2.

According to recent reports, sound. The VM has an ALSA sound card, and can play audio through your browser.

Network. curl, git clone and pip install work. Each TCP connection goes over one WebSocket to a Wisp relay.33Thank you to @_pi0_ for adding trynix.dev to his Wisp relay allow-list.

The best joke in Bernhardt’s talk is a browser running inside another browser: the Windows GIMP under Wine, in Chrome, in Firefox. Of course, I had to try it with trynix. 😈.

Here is Firefox in trynix, and it loading trynix.dev, and then loading Firefox again inside itself.44Don’t get too excited: this took over 4 hours. The inner Firefox needed JIT disabled, the middle one ran without GL, and the outer page used a Wisp relay on my laptop since wisp.unkernel.dev cannot reach itself.

Sit and bask in that insanity. That is Firefox, on Linux compiled to WebAssembly, in a Firefox tab, loading the site and then loading Firefox again inside itself. 🤯.
