HubSpot private apps can't be created anymore: what to use for server-side integrations

📑 Quick Jump: 1. Overview • 2. Key Details • 3. Closing Notes

If you've tried to create a private app in HubSpot recently and the option wasn't there, you're not doing anything wrong. HubSpot changed how server-to-server integrations get their credentials, and most tutorials online still describe the old path.

Private apps were the simple way to give a script access to your HubSpot data: create the app, pick scopes, copy a token. That flow is now closed for new legacy apps. HubSpot's direction is two credential types: project-based apps built with the developer platform, and Service Keys for straightforward data integrations.

For a typical marketing or sales operations script (read deals, read contacts, send events somewhere else), a Service Key covers it.

The one real limitation: Service Keys don't support webhooks. Webhooks need a project-based app built with the HubSpot CLI.

Nothing breaks today. Put two things on the calendar: replace the token with a Service Key, and move your endpoints to the date-versioned paths. Both are small changes if your code keeps the base path and the credential in configuration, not scattered through the script.

A common use for these scripts is closing the loop between HubSpot and Meta Ads: when a deal is qualified or won, an event goes to the Conversions API so campaigns learn which leads actually turn into customers. That's layer 4 of the 4-Layer Tracking Kit, which builds the whole path with a Service Key, the 2026-03 API and polling, including the HubSpot API pitfalls that return status 200 and do nothing.

Do my existing HubSpot private app tokens stop working?

It has been revealed that no. Tokens from legacy private apps that already exist keep working. What changed is that existing accounts can no longer create new legacy private apps. HubSpot has declared the end of support for legacy apps and for the v1 to v3 APIs in September 2027, so plan the migration before then.

What replaces private apps for a simple server-to-server script?

A Service Key. You create it in the account settings, give it only the scopes the script needs, and send it as a Bearer token. For a script that reads deals and contacts, read-only CRM scopes are enough.

Can I receive HubSpot webhooks with a Service Key?

It has been revealed that no. Webhooks require a project-based app built with the HubSpot CLI. With a Service Key, the robust alternative is polling the search API every few minutes for records modified since the last run.
