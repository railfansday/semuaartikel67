Jailbroken PS4 runs 9-billion-parameter AI model at up to 43 tokens per second

🌐 Source: Tomshardware • 📅 16 Nov 2026 • ⏱️ 4 min read (866 words, 📚 Deep Dive)

📑 Quick Jump: 1. Overview • 2. Key Details • 3. Closing Notes

Industry observers note that developer Leonardo Alegría’s open-source project Garlic LLM lets a jailbroken PS4 run the 9-billion-parameter Qwen3.5-9B AI model offline on the console’s 2013-era GPU. The app talks to the GPU directly, and the model is shrunk to about 4.5GiB to fit in the console’s memory, running at 31 to 39 tokens per second.

The project, named after the memory the GPU reads directly — its sibling memory type is “Onion” — relies on a PS4 running GoldHEN, which is a homebrew enabler for exploited consoles. Garlic LLM is a free, single 5.66GB download, available on Hugging Face and installable through the PS4’s Package Installer, with about 6GB free needed, or 12GB if the package is first copied to the console’s internal disk. The developer tested it on a base/Slim PS4 on firmware 11.52.

It’s capable of voice conversation, with spoken replies in seven languages through the Chatterbox speech model and the chat model running at about 22 tokens per second. A held controller button also lets it take dictation with Nvidia’s Parakeet TDT 0.6B v3 speech-to-text model, which supports 25 European languages. Parakeet models also power local transcription and dictation apps such as Meetily and Hex. The main model is Alibaba’s small open-weight Qwen3.5-9B, which, at the claimed 31 to 39 tokens per second in text chat — the prompt and test method are not given — is usable on the console.

The closest comparison is the PS5LM fork, which runs llama.cpp as a native app on the PS5 and reaches the console’s AMD GPU through PS5_Vulkan, a port of the RADV driver. The open-source llama.cpp is a widely used program for running language models locally, and RADV is the open-source driver that lets AMD GPUs run Vulkan, the graphics and compute API. On the PS4 there is no such driver layer for homebrew; Garlic LLM uses neither llama.cpp nor a Vulkan port, or so it would appear.

The model’s operations, such as matrix multiplies over 4-bit weights, are compute kernels written in OpenCL C and compiled with LLVM for AMD’s Graphics Core Next (GCN) architecture. The weights are kept in that “Garlic” memory, while the CPU side, in plain C, handles the tokenizer, the interface, text rendering, and audio. The pipeline runs from the prompt to the CPU tokenizer, then, for each token, a PM4 command buffer — the low-level commands a graphics driver would normally generate, which, in this case, the app builds itself — and the GCN kernels, before the token is displayed or spoken. The whole thing is built with the open-source OpenOrbis PS4 toolchain.

Recent findings suggest that one immediate question is how you fit a 9-billion-parameter model in the console’s 8GB of memory, which the CPU and GPU share. At 8 bits per weight, you have one byte per parameter, meaning you’d need at least 9GB, with typically more than that required overall. Part of the answer is 4-bit (“Q4”) weights, which take half as much, although 3-bit (“Q3”) weights, at about 3.5 bits with scales, are used for the two largest matrices in each layer.

According to recent reports, using the combination gets you to about 4.5GiB, versus about 4.9GiB if it were all 4-bit. The attention, or KV, cache is also 4-bit, which lets a 16K-token context fit, in comparison to the model’s native 256K. The Parakeet dictation model adds 0.33GiB and the Chatterbox voice models 0.29GiB and 0.09GiB, for a grand total of 5.23GiB, or 5.62GB, which closely matches the 5.66GB package size.

The next question is performance. Qwen3.5 comes with a multi-token prediction (MTP) head, and Garlic LLM uses it to draft up to two tokens ahead, with the full model verifying. This matches what the model was trained for, and the vLLM instructions on Alibaba’s model card use two speculative tokens. The project credits this for its chat speed on 2013 hardware.

It has been revealed that code also comes out faster with this setup, at up to 43 tokens per second. Also detailed is the default temperature, or model variability, which is 0.7 — Alibaba recommends 0.7 for general tasks with thinking off and 1.0 with it on — although the demo video uses 0, so it is predictable. At 35 tokens per second, the middle of the reported performance range, a 300-token answer takes under nine seconds. As a comparison, the PS5 ran the three-times-larger Qwen3.8-27B at about 20 tokens per second and the smaller Gemma 4 E4B and Llama 3.2 3B at 61 and 124, respectively, which is potentially quicker.

Sources indicate that the PS4 Pro is “not tested yet,” but the developer is asking users for reports on GitHub. The PS5 is not supported as the app is written specifically for the PS4’s GPU and system software. The app itself contains no exploit, but GoldHEN is installed at the user’s own risk.
