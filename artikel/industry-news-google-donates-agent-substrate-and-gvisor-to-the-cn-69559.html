InfoQ Homepage News Google Donates Agent Substrate and gVisor to the CNCF to Secure AI Agents at Scale.

Nov 20, 2026 2 min read.

Google has unveiled it is donating Agent Substrate and gVisor to the Cloud Native Computing Foundation (CNCF), placing two notable components of its AI agent infrastructure under vendor-neutral open-source governance. The move is intended to address two emerging challenges in running autonomous agents at scale: securely executing untrusted, AI-generated code and managing the substantial compute overhead created by agents that frequently pause and resume.

The announcement also includes OpenRL, Google's open-source reinforcement learning orchestration project. Together, the projects target different layers of agent infrastructure, from isolated code execution to managing agent lifecycles and coordinating large-scale training workloads. The goal is to establish an open foundation for agentic applications, much as Kubernetes helped standardise container orchestration.

Google argues that conventional Kubernetes workloads and AI agents have fundamentally different execution patterns.

In a recent development, A traditional application typically starts, serves requests, and continues running. An AI agent, however, may execute a tool or code for a few seconds before waiting for model inference, an external API, or human approval. Google estimates that agents can spend 90-95% of their time idle while still holding key state, including memory, files, repositories, and active sessions.

Sources indicate that keeping every agent in a dedicated Pod wastes resources, while scaling to zero introduces delays when environments must be reconstructed. At the other extreme, large-scale agent evaluations can overwhelm Kubernetes control planes when thousands of short-lived execution environments are repeatedly created and destroyed.

Google developed Agent Substrate to address these limitations by separating agent state (actors) from the compute resources (workers) used to execute it.

Actors represent individual agent sessions and retain their state, including filesystem contents, memory, and execution context. Workers provide reusable, pre-warmed execution environments drawn from shared Kubernetes pools.

According to recent reports, when an agent needs to resume, Substrate assigns it to an available Worker and restores its previous state. When the agent becomes idle, its state can be saved and the underlying compute resource released.

According to Google, this approach lets agents resume in under 500 milliseconds without creating a new Kubernetes Pod for every execution. It also reduces pressure on the Kubernetes control plane by managing agent lifecycles independently of individual Pod objects.

Sources indicate that the second major challenge is security. AI agents routinely execute generated shell commands, install packages, and interact with external tools. Treating this code as trusted creates significant risks, particularly when multiple agents share infrastructure.

Google's gVisor provides an additional isolation boundary through a user-space application kernel. Instead of letting containerised applications interact directly with the host Linux kernel, gVisor intercepts system calls and handles them within its own isolated environment.

This reduces the exposure of the underlying host while retaining much of the efficiency associated with container-based execution.

It has been revealed that agent Substrate also supports Cloud Hypervisor microVMs for workloads requiring hardware-level virtualisation. This gives platform teams flexibility to select an appropriate isolation boundary without changing the overall agent lifecycle model.

The announcement reflects a broader shift in cloud-native infrastructure. Kubernetes was designed around long-running applications and relatively stable workloads. Agentic systems introduce more dynamic execution patterns, where environments must be created, suspended, restored, and isolated at much greater frequency.

In a recent development, other providers are addressing similar challenges through technologies such as Kata Containers, Firecracker, and dedicated sandboxing platforms. Google's contribution is to combine secure execution with an agent-aware orchestration model and place the resulting technologies within an open ecosystem.

The wider implication is that AI agents need more than an orchestration framework and access to tools; they need their own secure, stateful, and efficiently managed execution infrastructure. By donating these projects to the CNCF, Google is helping establish the foundations for that next layer of cloud-native computing.
