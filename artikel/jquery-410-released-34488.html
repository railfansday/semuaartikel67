jQuery 4.1.0 Released

📑 Quick Jump: 1. Overview • 2. Key Details • 3. Closing Notes

jQuery 4.1.0 has arrived! And it brought a friend. Alongside the first minor release of the 4.x line, we're also releasing jQuery 3.8.0. A word of caution: 3.8.0 exists to release the fixes and improvements that have been pending on the 3.x-stable branch for the past few years, some of which you may recognize from the jQuery 4.0.0 release. It is a send-off, not a comeback. Going forward, the 3.x branch will only receive critical security and bug fixes. If you haven't yet made the jump to 4.x, we encourage you to do so — we have an upgrade guide and the jQuery Migrate plugin ready to help, and most users will be able to upgrade with minimal changes.

According to recent reports, as usual, the releases are available on our CDN and the npm package manager. Other third party CDNs will probably have them available soon as well, but remember that we don't control their release schedules and they will need some time. Here are the highlights.

A few changes landed on both branches, so you get these no matter which version you're on.

Custom AJAX transports have long received a completeCallback with positional arguments:.

Transports can now instead invoke the callback with a single object:.

In a recent development, this makes it possible for us to add new parameters in the future without relying on their order, and for transports to provide them selectively. In fact, 4.1.0 already takes advantage of it — see responseURL below.

The regular expression jQuery uses to match identifiers in selectors was vulnerable to catastrophic backtracking; a long chain of hex escapes followed by an invalid character — for example, in an attribute selector — could hang the page. The production now explicitly excludes digits & hex characters where the spec says it should, bringing us closer to spec and eliminating the ReDoS.

Recent findings suggest that IE & Edge Legacy sometimes throw on strict document comparisons (===) but not on loose ones (==). We switched most of these comparisons years ago, but a few leftovers remained in the selector code. They've now all been converted, avoiding some rare crashes in those browsers.

In a recent development, jqXHR objects now expose responseURL — the final URL of the request after any redirects followed by the browser. Following the existing responseText/responseXML/responseJSON pattern, it is only set when the transport can report it: modern-browser XHR provides it, while IE 11 and the script & JSONP transports do not.

Sources indicate that form-associated custom elements — custom elements registered with formAssociated = true — now serialize correctly with .serialize() and .serializeArray(). Elements that appear in form.elements are trusted to be submittable rather than being filtered out by a tag name check.

In non-XHTML XML documents, such as XSLT-transformed documents, elements created with document.createElement land in the XML namespace and have no style property, which broke jQuery's CSS support tests. jQuery now uses createElementNS with the XHTML namespace internally, so .css() and friends behave in these documents.

jQuery no longer uses getElementsByTagName or getElementsByClassName internally, relying on querySelectorAll instead. In today's browsers, qSA is on par with or faster than the old methods, and returns a static list rather than a live collection that we had to snapshot. The switch also fixes some long-standing bugs, including MathML elements not being found by lowercase tag names on cloned nodes in IE 11, selectors with leading combinators not working on document fragments, and selection by tag names containing less common symbols such as dots.

Related selector work makes the quick selection paths stricter about what counts as a simple tag or class selector — with a fallback to regular selection when qSA throws — and invalid escape sequences in selectors are now decoded to U+FFFD, the replacement character, as the CSS specification requires.

jQuery.uniqueSort removes duplicates with a single-pass, two-pointer compaction instead of repeated splices, taking the duplicate removal from O(N²) time and O(N) extra space to O(N) time and constant space. Behavior and ordering are unchanged; large disconnected sets just get there faster.

Sources indicate that again, most of what's in 3.8.0 has been sitting on the branch for a while, and much of it will look familiar if you read the jQuery 4.0.0 release post. But there are a few things specific to 3.x.

The hidden attribute used to be a boolean attribute, but it has since gained the until-found value. jQuery 3.x normalized boolean attributes in a way that clobbered that value; .attr( "hidden", "until-found" ) now sets it as-is. jQuery 4.x changed how boolean attributes are handled precisely to avoid this class of problem, so no change was needed there.

Two sets of APIs that were removed in jQuery 4.0.0 are now formally deprecated in 3.x, which means the jQuery Migrate plugin can warn you about them before you upgrade:.

3.8.0 also picks up a number of fixes that already shipped in jQuery 4.0.0, including support for self-removing scripts passed to .html(), a fix for jQuery.cleanData skipping elements during cleanup, correct dimensions for table elements, more robust native event handling in leverageNative, and support test fixes for pages under CSS zoom and initially hidden iframes.
