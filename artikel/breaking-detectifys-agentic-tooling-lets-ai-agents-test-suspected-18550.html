Breaking: Detectify’s Agentic Tooling lets AI agents test suspected flaws in running applications

UPDATED 03:00 EST / NOVEMBER 16 2026.

Swedish application security company Detectify AB today debuted Agentic Tooling, a set of tools aimed at letting an organization’s own artificial intelligence agents test whether suspected vulnerabilities can be exploited in running applications.

A new Security Ledger, also part of the launch, is designed to record the evidence behind each test. Detectify is pitching the release at DevSecOps teams that are unsure whether they can trust what their AI agents report.

Detectify customers report that roughly 80% of the findings from their AI-driven static application security testing tools are noise. Under pressure to deliver an answer, an agent can also produce a convincing report about a test it never ran, the organization warned.

Even before AI agents enter the picture, many security teams are falling behind. Nine in 10 open critical and high-severity vulnerabilities had stayed exposed for more than 90 days, according to Detectify’s H2 2026 Cyber Hygiene Index. In a study by researchers at Fudan University and Tencent Holdings Ltd., 76% of the static-analysis alerts examined were found to be false positives. Each one took developers 10 to 20 minutes to review.

Through Agentic Tooling, agents can tap the testing engines Detectify has built over more than a decade. Included are payload assessments sourced from its ethical hacker community, attack surface data from its Surface Monitoring product and Alfred, an AI system the company launched in March 2025 to automate tests for known vulnerabilities.

Running in a customer’s own environment, the tools connect to agents through either the Model Context Protocol or a command-line interface. They operate only on the data a customer provides and are said to work with whichever agent the customer already uses.

At the center of the design is loop engineering, an emerging practice of running AI agents in automated, repeating workflows rather than prompting them by hand. Kicking off each loop is a trigger such as a continuous integration run. Whether it comes from a code scan, a bug bounty report, a red team or Detectify’s own attack surface data, each finding is turned into a ticket.

Once an agent picks up a ticket, it reads the relevant code before testing the live application from the outside, as an attacker would. Run continuously, the loop becomes what Detectify calls a verification factory.

The requests sent, the payloads used and the results returned are all logged in the Security Ledger each time an agent uses Detectify’s tools. Written by Detectify rather than the agent, the append-only ledger lets teams separate findings backed by actual tests from unsupported AI conclusions. Any ticket that could cause harm, such as a denial-of-service test, is marked unsafe for a person to decide on.

Recent findings suggest that “Ask an agent to write your code, then ask the same agent whether it’s secure. If it says yes, you don’t actually know,” mentioned co-founder and Chief Executive Rickard Carlsson. There are plenty of examples of agents fabricating proof to please the person asking, according to Carlsson, who described Detectify’s aim as “building proof that an agent can’t fabricate.”.

Recent findings suggest that available on request starting today, Agentic Tooling builds on the Detectify MCP Server that the tech giant announced in May to give AI agents access to its security findings. Investors include Insight Partners, which took a majority stake in October 2024, along with Balderton Capital (UK) LLP, Inventure, First Fellow Partners Oy and SquareOne App Ltd.
