InfoQ Homepage News .NET MAUI 11 Makes CoreCLR the Default Runtime and Adds Incremental XAML Hot Reload.

Nov 26, 2026 3 min read.

Sources indicate that microsoft released .NET 11 on 10 November, and .NET MAUI in .NET 11 changes the default runtime from Mono to CoreCLR on all supported platforms. It also adds incremental XAML hot reload, implicit XAML namespaces and latest test project templates. The work spanned seven previews and a release candidate, and the documentation describes product quality as the release's focus. Overall, this release consolidates more than it expands.

.NET MAUI (Multi-platform App UI) is Microsoft's cross-platform UI framework for Android, iOS, Mac Catalyst and Windows apps built from one C# and XAML codebase. .NET 11 is a Standard Term Support release with two years of support. Microsoft notes that MAUI follows its own support policy, separate from the runtime's STS and LTS lifecycle.

Industry observers note that the runtime switch is the most significant change. According to Microsoft, CoreCLR puts mobile and desktop apps on the same runtime as the other .NET workloads. Release builds use composite partial ReadyToRun by default. On Apple platforms, which disallow JIT compilation, code that isn't precompiled runs in the CoreCLR interpreter. Native AOT is an opt-in publishing option, and its Android support is still experimental. Microsoft recommends developers to test app libraries before choosing their deployment model.

It has been revealed that XAML gets four main improvements. First, incremental hot reload, still in preview, patches live instances of pages and controls without recreating them. It is on by default in Debug builds, works with dotnet watch, and can be disabled with EnableMauiIncrementalHotReload. Second, implicit namespace declarations are now on by default, so the root xmlns and xmlns:x are optional. Third, lazy ResourceDictionary loading makes large dictionaries initialise up to roughly eight times faster when XAML source generation is used. Finally, RelativeSource bindings with a resolvable AncestorType now compile to trim-safe code.

Handlers keep replacing the legacy renderers with newer implementations. Windows uses the new CollectionView2 handler by default, Android Shell is now handler-based, and iOS and Mac Catalyst now use handlers for NavigationPage, TabbedPage and FlyoutPage. The old renderers remain available as a manual fallback. On iOS, Appearing now fires before a page is pushed rather than after it becomes visible, and secondary toolbar items move into an overflow menu. Developers who depend on the old timing should switch to NavigatedTo.

Controls get smaller additions. Maps gain clustering and custom pin icons, plus an Azure Maps-backed implementation on Windows. TabbedPage gains badges, BoxView a Fill brush, and LongPressGestureRecognizer becomes configurable. Shell also supports route templates such as trip/{tripId}.

In a recent development, animation methods now accept a CancellationToken, and their non-Async variants are obsolete. On the platform side, a new Passkeys class in Microsoft.Maui.Authentication wraps WebAuthn creation and assertion, while the server still has to validate challenges and attestation. Permissions.PostNotifications now works on iOS, and splash screens can have dark-mode variants.

For Android, the minimum API level rises from 21 to 24, and x86 architecture is no longer supported. The release notes report shorter builds: an incremental build after a managed source change dropped from 68.3 to 52.3 seconds. They also report startup gains of 2.4 to 4.5 per cent from partial ReadyToRun, at the cost of a slightly larger package. Apple targets now require iOS, tvOS and Mac Catalyst 18.2 and macOS 15.2, with Xcode 26.4.

It has been revealed that several changes break existing code. The Microsoft.Maui.Controls.Compatibility package no longer ships, the Color record is now sealed, Java.Lang.Object.JavaFinalize() is obsolete, and non-font SwipeItem icons are no longer tinted automatically. When upgrading, Microsoft advises to focus on throughly testing navigation, custom handlers and trimmed publishing.

The full list of changes, including per-preview release notes, is in the .NET MAUI documentation. .NET MAUI ships as a workload with NuGet packages, so a project can pin specific versions.
