When developers talk about high-performance mobile games, the Android NDK samples by Bruno Oliveira are often cited as the gold standard for clean, low-level C++. But as an iOS developer, I wanted to see if I could take that same “pure” C++ logic and make it sing on an iPhone.

My latest project, TunnelFeveriOS, is the result of that journey. It isn’t just a port; it’s a blueprint for building a custom game engine.

The original Endless Tunnel is built to live within the Android lifecycle (JNI, Activity, and NDK). Moving this to iOS required more than just hitting “compile.” I had to build a Platform Abstraction Layer.

Recent findings suggest that to make the C++ engine talk to the iOS UI, I utilized Objective-C++ (.mm** files)**. This allowed me to keep the game's high-speed math and geometry in native C++ while using Cocoa Touch to manage the windowing and touch input. In TunnelFeveriOS, you’ll see how the view controller manages the game loop, feeding time deltas and touch coordinates directly into the C++ core.

Industry observers note that since the original game uses OpenGL ES, I leveraged iOS’s GLKit framework. The trick was ensuring that the shaders and vertex buffer objects (VBOs) originally written for Android were correctly initialized within the iOS EAGLContext. The result? 60 FPS performance that feels native because, at the machine level, it is.
