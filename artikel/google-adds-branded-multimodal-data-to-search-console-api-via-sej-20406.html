📑 Quick Jump: 1. Overview • 2. Key Details • 3. Closing Notes

In a recent development, google has declared that it is adding three features from its Search Console Performance report to the Search Analytics API. This means website developers and tool makers can build these features directly into their automated reporting systems.

According to Google’s blog post announcing this, the API now supports the branded queries filter, multimodal web search data (web multimodal), and filters that are able to track multiple countries or device types within one API call.

The blog post explains how all three items have been available in the Performance report since they were first implemented. The post then describes the API versions as a solution to “stitching together separate requests or maintaining complex keyword regex lists”.

Your API results can now include a brandedClassification dimension, which enables you to use either the values BRANDED or NON_BRANDED for filtering or grouping based on branded vs. non-branded searches. According to the API reference documentation, this upcoming dimension provides data only for top-level properties, starting Feb. 21, 2026; however, if a property does not meet the required number of queries and impressions, you will receive an empty table (no rows), the blog post says.

The API reference documentation also states that the branded classification dimension field accepts only the equals operator, and you cannot apply filters or groupings with it in requests with a query filter applied.

Google’s earlier announcement highlighted the branded and non-branded options in the Performance report:.

In March, a Search Console user posted a question noting that their branded breakdown only started at approximately Feb. 21. They then asked if it would be possible to have prior data broken out into two different categories. Google’s John Mueller responded that there is “a point when the data starts being tracked,” as reported by Roger Montti.

Searches with Google Lens provide multimodal performance metrics when type is set to webMultimodal, as do Circle to Search on an Android device and uploading images to Google Search, according to the reference.

Industry observers note that after multimodal reporting was enabled by Search Console on Sept. 24, I reported that the API reference did not have a separate multimodal type value listed. The reference, last updated Nov. 16, now lists one.

Google’s September announcement illustrated the multimodal option in the report’s search-type filter:.

Sources indicate that google’s September announcement also listed Chrome’s right-click “Search this image” feature, and the Performance report help page includes Chrome image search. The API post and reference don’t mention Chrome.

The Nov. 16 post states multimodal data “will also be available in BigQuery for properties with an active bulk data export” but doesn’t give a date. As of Nov. 16, the bulk export table reference lists six search types, with no multimodal value yet.

A brand-newly introduced field, filterLists, enables people to filter results by multiple countries or multiple devices in one request. The examples given in the post are country-based groupings like EMEA, LATAM or DACH.

The reference limits filterLists to country and device dimensions and matches on exact values only. People cannot use the same dimension (country or device) in filters and in filterLists in the same request.

On eligible properties, the upcoming feature allows teams using the API to capture a branded/non-branded split in their reporting tools, starting Feb. 21, 2026. For data prior to this date, the API’s split has no ability to break out branded vs. non-branded search traffic.

It has been revealed that google uses an AI-assisted process to determine which searches are branded or non-branded. According to Google’s November 2025 announcement, “some queries may occasionally be misidentified”. To identify discrepancies, run the API branded/non-branded split alongside a brand regex you have been using and see where they differ.

As of Nov. 16, the API reference does not indicate if web results include webMultimodal data. Before adding your web and webMultimodal totals together, check how your API web numbers match against the text-based and multimodal numbers in the Performance report.

As of Nov. 16, neither Google’s post nor the API reference explains how far back webMultimodal data goes. Check the API reference and the bulk export table reference for a BigQuery date, the start date for multimodal history, and any mention of Chrome image search.
