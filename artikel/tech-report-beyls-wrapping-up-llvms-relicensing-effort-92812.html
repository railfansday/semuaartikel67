Tech Report: Beyls: Wrapping up LLVM's relicensing effort

📑 Quick Jump: 1. Overview • 2. Key Details • 3. Closing Notes

Kristof Beyls has published a summary to the LLVM discussion forum to announce that the project is declaring success and bringing its relicensing effort to a close after eight years.

In a recent development, we've been asking past contributors to relicense their work since 2018. Fresh contributions have come in under Apache-2.0 WITH LLVM-exception since January 19, 2019. Code contributed before that date was under LLVM's earlier licenses (UIUC/NCSA, plus MIT for some runtime libraries), so we needed permission from its authors to move it over. [...].

Recent findings suggest that rather than trying to "chase the last tiny fraction forever" LLVM is winding up the effort. Any contributors with code contributed before January 19, 2019 who have not signed a relicensing agreement and do not want their contributions made available under Apache-2.0 with the LLVM-exception can still reach out to the project to ensure their code has the appropriate SPDX license identifier.

That Apache-2 licensed compilers (which insert some compiler code into the executables they create) don't create Apache-2 obligations for the programs they create. 2. It fixes incompatibility with GPLv2 by saying that, for a combined work of Apache-2 plus GPLv2 code, if an authority decides that any clause of Apache-2 is incompatible with GPLv2 then that clause of Apache-2 doesn't apply. (Which I guess they decided is fine because the places where there could be conflicts, such as patents, using the GPLv2 version isn't enough of a problem to be worth incompatibility.) So, the LLVM exception looks like a pretty good instrument.
