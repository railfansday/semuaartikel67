Sources indicate that crypto exchange Binance has warned iPhone users about an iOS vulnerability that could allow malicious apps to access sensitive data stored by other apps. Here are the details.

In a post published on X (via AppleInsider), Binance notes that a vulnerability called worse_query could allow “malicious apps to read local files from other apps, putting seed phrases, private keys, and login credentials at risk across the entire ecosystem.”.

Binance claims the flaw affects iOS 26.7.1, iOS 27.0.1, and iOS 27.2. However, a Community Note points out that researchers describe the vulnerability as an unpatched zero-day and that Apple’s latest security updates, including iOS 27.2.1 (the current version at the time of writing), do not mention a fix.

It has been revealed that A vulnerability (worse_query) affecting iOS 26.7.1, 27.0.1, and 27.2 allows malicious apps to read local files from other apps, putting seed phrases, private keys, and login credentials at risk across the entire ecosystem. This is an iOS-level matter, not unique to Binance.….

The vulnerability was disclosed by security researchers @0xjohnny and @forcequitOS, who published a proof of concept on GitHub demonstrating how it can be used to bypass iOS sandbox protections, which normally prevent apps from accessing each other’s files.

Researcher @forcequitOS also noted that neither iOS 27.2.1 nor iOS 27.3 beta 1 patches the vulnerability.

In a recent development, just as a general statement so there isn’t any confusion about it, worse_query is *not* patched in iOS 27.2.1 and 27.3 beta 1. I’ll update version support on the readme when it’s patched.

Although the researcher describes the code as intended for developers and not useful on its own, other developers have already built apps using it, including a file manager that can access, modify, and delete data belonging to other apps without requiring a jailbreak.

According to The Hacker News, neither Binance nor the researchers have reported any attacks or cryptocurrency thefts involving the vulnerability so far.
