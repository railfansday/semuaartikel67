📑 Quick Jump: 1. Overview • 2. Key Details • 3. Closing Notes

In a recent development, freeBSD pkgbase finally brings the base OS to you as discrete packages instead of monolithic tarball "package sets". However, if you want to deploy a lot of systems or FreeBSD jails you will be hitting the official FreeBSD mirrors repeatedly which is not ideal. I have my own internal package repository where I build packages from source, but I don't do that for the base OS and do not intend to; there's really no changes that I would want to make to the builds and having the base OS match the official upstream releases is crucial for ensuring their integrity and being able to report any bugs you encounter.

It has been revealed that this problem started to become very obvious to me when I was converting all of my FreeBSD jails to pkgbase deployments as the process wasn't caching the packages anywhere locally and each conversion was hitting the official mirrors over and over -- 36 times if I didn't intervene. This is a lot of bandwidth wasted when I could just mirror it locally. So I did, and this is how you can do it too.

Recent findings suggest that believe it or not, I'm still using Apache for a few things. If someone wants to share a similar configuration for Nginx I'll publish that as well.

It has been revealed that the one thing that bit me was that initially I pointed the reverse proxy configuration to pkg.freebsd.org. This won't work because that server will redirect you to a CDN and Apache won't read through the redirect and cache it, so I pointed directly to the CDN right now. This absolutely will change in the future when the CDN is completely hosted by the FreeBSD project again, but for now this is the requirement.
