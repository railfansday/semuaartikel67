On Nov. 17, Chrome 158 rolls out to the majority of desktop and mobile people and drops support for client-side XSLT (Extensible Stylesheet Language Transformations).

For years, WordPress core and major SEO plugins, including Yoast SEO, Rank Math, and All in One SEO (AIOSEO), have referenced an .xsl stylesheet inside their XML sitemaps. When a person opened a sitemap URL in a browser, Chrome executed that XSLT file to transform the underlying XML code into a clean, clickable HTML table.

Without XSLT support, opening a WordPress sitemap in Chrome 158 displays raw, unstyled XML markup alongside a browser console and page warning.

Screenshot from author, November 2026.

Search engines do not use XSLT. Googlebot, Bingbot, and other web crawlers fetch and parse the raw XML nodes (, ) at the source. Crawlers avoid browser-side stylesheets, meaning indexing, crawl efficiency, and search rankings remain unaffected.

Because Chrome 158 lands while Google’s November core revision, which began on Nov. 10, is still rolling, site owners and clients checking their domains during routine ranking audits may panic when they see raw XML in place of the familiar formatted table.

In a recent development, XML sitemaps exist for machine consumption, and search engine bots read the underlying and tags. Dropping visual styling changes nothing about URL discovery, crawl budget, or search visibility.

Because Chrome 158 arrives alongside the November core patch, clients or stakeholders who inspect their sitemap URLs will spot unformatted XML code and assume a site outage or plugin failure caused ranking fluctuations.

According to recent reports, chrome logs a deprecation warning in DevTools whenever a page invokes an .xsl stylesheet. Automated site-health crawlers or QA tools that monitor browser console errors may flag sitemap URLs until plugins or WordPress core drop the stylesheet reference.

Editors and junior marketers who relied on opening /sitemap_index.xml in Chrome as a quick directory of site URLs lose that visual table unless they switch browsers (such as Firefox or Safari, which retain XSLT for the time being) or use a dedicated HTML sitemap.
