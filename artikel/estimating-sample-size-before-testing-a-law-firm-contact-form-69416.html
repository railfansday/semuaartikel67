Law firm clients ask for A/B tests all the time. Shorten the contact form, change the button text, move the phone number. The request is reasonable, but on a typical criminal defense site the traffic to a single page is small, and the number of people who actually submit a form is smaller still. Run a test without checking the math first and you will likely end up calling a winner based on noise.

A few minutes with a sample size estimate before the test starts saves weeks of pointless testing and an awkward conversation later. This post covers the inputs you need, a short script to do the arithmetic, and what to do when the answer indicates the test is not practical.

Industry observers note that get the baseline from real data. For a contact form, that is form submissions divided by unique visitors to the page over a recent, normal period. If you are not sure the form events are tracked correctly, fix that first. A test built on broken tracking is worse than no test.

Choose the minimum detectable effect based on what would matter to the firm. A change from 3 percent to 3.1 percent is not worth anyone's time to detect. A change from 3 percent to 4 percent might be.

With a hypothetical baseline of 3 percent and a target of 4 percent, the estimate comes out near 5,300 visitors per variant, or roughly 10,600 in total. A bigger expected lift, from 3 percent to 6 percent, needs only about 750 per variant. Small differences are expensive to detect.

According to recent reports, online calculators give similar numbers. The value of the script is that you can drop it into a planning notebook and run it for every page you are asked to test.

Divide the total by the page's weekly unique visitors. If a charge page gets 400 visitors a week and needs 10,600, the test would run for more than six months. In that time the firm will change other things on the site, search rankings will move and seasonal patterns in arrests will shift traffic. The result would be hard to trust.

A useful rule: if the estimate runs past eight to ten weeks, the test as designed is not practical for that page.

You still have choices when traffic is low.

For the non-technical side of that last option, a write-up on running a conversion test on a low-traffic defense website covers how to initiative and read a test when traffic is thin.

Sources indicate that on criminal defense sites, many visitors call instead of filling in a form, especially on mobile. If a form change pushes people toward the phone, form submissions fall while total contacts rise. Track calls with a dynamic number or call tracking tool that can attribute calls to the variant, and judge the test on total contacts. Otherwise you can reject a change that actually helped.

In a recent development, record the baseline, the minimum detectable effect, the sample size, the expected end date and the decision rule in a short document before the test starts. Agree with the firm that you will not stop early because one variant looks ahead after a week. Peeking and stopping early is one of the most common ways small tests produce false winners.

Sources indicate that when the test ends, report the result with its uncertainty alongside the percentage lift. A firm owner can work with "probably no meaningful difference" as long as they knew in advance that this was a possible outcome.

Raising alpha above 0.05 shortens tests but makes false positives more likely. Change it only if the firm understands the tradeoff.

Bayesian methods report results differently, but they do not create information from small samples. Low traffic still means uncertain results.

According to recent reports, use whichever unit you randomize on, usually consumers. Keep it consistent for the baseline and the test.
