In periods of competing blocks, Solana validators spend CPU and timing resources replaying blocks that will never make it into the canonical chain once another competing block from the same slot has been finalized.

Recent findings suggest that this PR proposes changes to validator software to help prevent work from being done. It also decouples functionality and gives control to Votor in requesting slot cancellation without modifying BankForks.

Overall, this is a reasonable technical improvement and has a good engineering motivation. Further technical comments and review would be helpful to understand if there are potential race conditions or complications with reliability of replay and consensus. This could be split into two PRs to make it easier to test and review.

There are two main proposed changes:.

Make sure that the replay thread doesn't block on the scheduler finishing processing blocks.

Add slot cancellation, where Votor can tell replay which blocks to stop trying to process.

There was an earlier PR (PR #16454) which attempted to solve a similar problem, but that PR included some complexity around being able to pause and resume block processing.

This PR attempts to solve a similar problem in a simpler way by adding slot cancellation. It allows validators to stop replaying blocks that will never make it into the canonical chain once another block from the same slot has been finalized.

Sources indicate that this is an efficiency-focused change to validator software. It's not intended to have a particular effect on transaction throughput or SOL price. For Solana to continue to perform well, it's vital not only to continue to increase TPS but also continue to find ways to make sure that validators aren't doing unnecessary work.

Industry observers note that for everyday users, it's unlikely there would be noticeable effects from this change. Sending/receiving SOL, using a DEX, using DeFi more broadly, and using any other Solana-powered website/app should all continue to function as normal. It's possible that users could see some benefits from this change in the form of Solana being more performant in the face of heavy compute loads.
