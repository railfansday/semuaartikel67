How to Self-Host Plex and Jellyfin: A Developer's Field Guide to Your Own Streaming Stack

📑 Quick Jump: 1. Overview • 2. Key Details • 3. Closing Notes

According to recent reports, the first time I cancelled Netflix and tried to watch my own ripped movies on a hotel TV, nothing played. The file was H.265 10-bit in MKV. The TV didn't support it. The browser transcoder choked. My "save $20 a month" project turned into a weekend of reading about hardware transcoding, and that's the moment you realize media streaming is genuinely hard. This article is the guide I wish I'd had then.

Industry observers note that plex and Jellyfin both solve the same problem-your media library, served to your devices, with metadata, posters, and a Netflix-like UI. Plex is the polished commercial product with a paywall on the good features. Jellyfin is the AGPL-licensed fork of Emby that doesn't phone home and doesn't ask for a credit card. Most developers I know end up running both for a few weeks and picking a side. I'll show you how to run either (or both) on real hardware, with real transcoding, behind a real reverse proxy, reachable from anywhere.

It has been revealed that both projects are mature, both play every common format, both support hardware transcoding. The differences are about philosophy and friction.

I run Jellyfin in production. I run Plex on a second box for family members whose Smart TVs don't have a Jellyfin app. If your household is mostly Apple TV, Plex is still the safer bet. If everyone's on Roku/Fire Stick/web, Jellyfin is fine and you'll save the Plex Pass fee.

A typical self-hosted media stack looks like this:.

┌──────────────────────────┐ │ Internet / Tailscale │ └────────────┬─────────────┘ │ HTTPS ▼ ┌──────────────────────────┐ │ Caddy reverse proxy │ │ (auto TLS via ACME) │ └────────────┬─────────────┘ │ ┌──────────────────┼───────────────────┐ │ │ │ ▼ ▼ ▼ ┌────────────┐ ┌──────────────┐ ┌──────────────┐ │ Jellyfin │ │ Plex │ │ *arr stack │ │ (Docker) │ │ (Docker) │ │ (Radarr / │ │ │ │ │ │ Sonarr / │ │ /dev/dri │ │ /dev/dri │ │ Prowlarr) │ │ render │ │ render │ │ │ └─────┬──────┘ └──────┬───────┘ └──────┬───────┘ │ │ │ ▼ ▼ ▼ ┌──────────────────────────────────────────────────┐ │ /mnt/media ← mergerfs( /mnt/disk{1..N} ) │ │ │ │ SnapRAID parity: /mnt/parity (1 disk) │ └──────────────────────────────────────────────────┘.

The key design decisions are: services in Docker, all media mounted read-only inside containers, hardware acceleration passed through /dev/dri, and one reverse proxy handling TLS for everything.

Industry observers note that keep the host layout boring and predictable. Every service gets a config dir under /opt, every persistent dataset under /mnt.

plaintext /opt/jellyfin/ # config, metadata cache, transcode dir /opt/plex/ /opt/caddy/Caddyfile /mnt/disk1/ # individual data disks, mounted at boot /mnt/disk2/ /mnt/parity/ # SnapRAID parity /mnt/media # mergerfs view of disk1..N ├── movies/ ├── tv/ ├── music/ └── photos/.

Recent findings suggest that /mnt/media is the only path the containers see. If you ever migrate disks or rebuild the pool, the container mounts don't change.

A single significant disk is the easy path until it dies. RAID 5 rebuilds are stressful on modern high-capacity drives and the array is slow while it runs. The homelab consensus is mergerfs (file-level concatenation, no striping) plus SnapRAID (snapshot parity, run nightly).

shell sudo apt install mergerfs snapraid.

conf /dev/disk/by-id/ata-WDC_WD40EFRX-1 /mnt/disk1 ext4 defaults,noatime 0 2 /dev/disk/by-id/ata-WDC_WD40EFRX-2 /mnt/disk2 ext4 defaults,noatime 0 2 /dev/disk/by-id/ata-WDC_WD40EFRX-3 /mnt/parity ext4 defaults,noatime 0 2.

/mnt/disk1:/mnt/disk2 /mnt/media fuse.mergerfs \ defaults,allow_other,category.create=mfs,moveonenospc=true,dropcacheonrename=true 0 0.

conf parity /mnt/parity/snapraid.parity content /mnt/disk1/snapraid.content content /mnt/disk2/snapraid.content content /opt/snapraid/snapraid.content data d1 /mnt/disk1/ data d2 /mnt/disk2/ exclude *.unrecoverable exclude /tmp/ exclude /lost+found/ exclude *.!sync exclude *.bak.

set -euo pipefail LOG=/var/log/snapraid.log { echo "=== $(date) ===" snapraid sync snapraid scrub -p 8 -o 1 } >> "$LOG" 2>&1.

Recent findings suggest that crucially: mergerfs is not RAID. If a disk dies before SnapRAID has run, the files written since the last sync are gone. SnapRAID is snapshot parity, not real-time. This is the trade-off. For movies you can re-rip, that's fine. For irreplaceable photos, back them up off-site too.

Direct play is when the client can decode the file as-is. Transcoding is when the server has to convert it on the fly. 4K HEVC to 1080p H.264 in software will pin 8 cores and deliver 4 FPS. The fix is hardware: pass /dev/dri into the container and let the iGPU do it.

Recent findings suggest that vainfo should list VAProfileHEVCMain10 and VAProfileVP9Profile0. If you don't have it, install intel-media-va-driver-non-free on Debian/Ubuntu.

Add your media user to the render group so the container can access the device:.

shell sudo usermod -aG render jellyfin sudo usermod -aG render plex.

It has been revealed that the classical symptom of "transcoding doesn't work" is the server going to 100% CPU and the video pausing every few seconds. That's software transcoding. The container is missing /dev/dri or the render group permission.

In a recent development, here's a production-ready compose file. Note the /dev/dri device, the render group ID mapped via group_add, and the explicit no-new-privileges security option.

services: jellyfin: image: jellyfin/jellyfin:10.9.11 container_name: jellyfin restart: unless-stopped user: "1000:1000" group_add:.

Inside Jellyfin, enable VAAPI under Dashboard → Playback → Transcoding. Pick /dev/dri/renderD128 as the device. Test with a 4K HEVC file forced to 1080p max and a 20 Mbps bitrate cap-CPU should stay under 10%.

Plex is similar but the image expects a claim token from plex.tv on first boot.

services: plex: image: plexinc/pms-docker:latest container_name: plex restart: unless-stopped hostname: plex devices:.

In a recent development, plex Pass is required for hardware transcoding. Without it, you'll see "Transcoding (cpu)" in the dashboard and CPU will spike. Don't waste a weekend debugging the /dev/dri perms if you haven't bought Plex Pass yet-it's gated behind the feature flag.

It has been revealed that plex uses network_mode: host because it broadcasts on multiple ports (32400 main, 32469 DLNA, 1900/5353 UDP for discovery). You can run bridge mode with explicit port mappings, but DLNA auto-discovery will break for clients that rely on it.

You want HTTPS for remote access and you want a single port forwarded. Caddy is the lowest-friction option because ACME is built in.

jellyfin.example.com { reverse_proxy 127.0.0.1:8096 { flush_interval -1 } encode zstd gzip.

# Jellyfin's recommended headers header { Strict-Transport-Security "max-age=31536000; includeSubDomains; preload" X-Frame-Options SAMEORIGIN X-Content-Type-Options nosniff Referrer-Policy no-referrer # don't apply Caddy's default CSP, Jellyfin sets its own ?Content-Security-Policy "" }.

@websockets { header Connection Upgrade header Upgrade websocket } reverse_proxy @websockets 127.0.0.1:8096 }.

plex.example.com { reverse_proxy 127.0.0.1:32400 encode zstd gzip }.

The flush_interval -1 is critical for Jellyfin-it disables buffering so streaming chunks reach the client immediately. Without it, you'll see 30-second startup stalls on every video.

services: caddy: image: caddy:2.8-alpine container_name: caddy restart: unless-stopped ports:.

If you'd rather not open ports on your router, skip this whole section and use Tailscale.

Cloudflare Tunnel's free ToS technically excludes "large file streaming." People do it anyway and most accounts never get flagged, but if you care about the letter of the agreement, don't. Use Tailscale for family-if they can install a phone app, they can use Tailscale. Use port forwarding + Caddy for yourself.

shell curl -fsSL https://tailscale.com/install.sh | sh sudo tailscale up --advertise-tags=tag:media.

Both Plex and Jellyfin have hard opinions about file layout. Get this wrong and metadata matching turns into a part-time job.

plaintext /mnt/media/movies/ The Matrix (1999)/ The Matrix (1999) [1080p] [Bluray].mkv The Matrix Reloaded (2003)/ The Matrix Reloaded (2003) [1080p] [Bluray].mkv.

/mnt/media/tv/ Breaking Bad (2008)/ Season 01/ Breaking Bad - S01E01 - Pilot.mkv Breaking Bad - S01E02 - Cat's in the Bag.mkv.
