📑 Quick Jump: 1. Overview • 2. Key Details • 3. Closing Notes

A maze generator is easy to write badly. Carve some passages, knock down some walls, ship it — and sooner or later it hands you a maze where the goal is walled off completely. In a game that's an unwinnable level. In a printed activity book, that's a kid discovering the answer key doesn't work, and a refund instead of a review.

In a recent development, so the maze generator I built for my books doesn't just carve — it proves. It walks the finished maze from start to goal before anything ships, and the proof travels with the puzzle. This is that generator, exposed as an API called ActivityForge. In this tutorial we'll call it from Python: send a size and a seed, get back a maze, its wall data, and the verified solution path.

According to recent reports, the API lives on RapidAPI. The free tier gives you 100 calls a day, and every plan — free included — reaches every endpoint and every format. The paid intends only change how many calls you get, starting at $19/month. Nothing in this tutorial needs a paid plan.

The whole request is one POST. Two headers carry your key and the host; the JSON body carries the maze settings.

A few things worth knowing about the parameters:.

The response describes the maze as data, not a picture. Coordinates are [x, y] — x is the column, y is the row — with start at the top-left cell [0, 0] and goal at the bottom-right. The walls field is a list of rows; each cell carries four booleans, top, right, bottom, and left, saying which of its walls stand. That's everything a renderer needs:.

That's a real response, not a mockup — seed 42 will hand you this exact maze every time.

Here's the part that makes the maze safe to ship. Alongside the walls, the response carries a solution object: path (the route as [x, y] cells, start to goal), directions (the same route as words — right, down, left, up), and steps (the move count).

The generator builds a perfect maze — a spanning tree over the grid, so exactly one route joins any two cells — then breadth-first walks that route before returning anything. The solution is the route it walked, so it can't disagree with the walls. Feed the path back into the renderer as marked cells and the proof draws itself:.

In a recent development, trace the stars yourself: every step moves through a gap, never through a wall, from the S in the top-left to the G in the bottom-right. Generating levels? That directions list doubles as a walkthrough your game can replay. Printing? It's the answer key.

It has been revealed that because we asked for format: "all", the same response also carries svg (a print-ready page) and pdf_base64 (a vector PDF, base64-encoded). Saving the PDF is three lines:.

That's the page you hand to a kid — titled, with "Find your way from START to GOAL!" on it, no drawing required.

Look back at the request: "seed": 42. Run it tomorrow, next month, on a different machine — same maze, wall for wall, same 38-step solution. Leave the seed out and every call returns a fresh random maze. For print: generate a catalog once, record the seeds, re-render identical puzzles forever. For a game: a daily maze that's identical for every player, from one integer.

Every generator proves its own output the same way — word placements re-checked against the finished grid, dot sequences checked complete and ordered — because a broken puzzle in a printed book is a refund, not a bug report.
