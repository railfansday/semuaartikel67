AWS Releases Strands Decider V2 and Sandboxes More Coding Agents

Amazon Web Services released five open-weight Strands Decider v2 models on November 23, 2026, and added native Claude Code, Codex, and Kiro CLI support to its open-source Strands Box sandbox, targeting the inference cost of routine agent decisions and the security of unattended coding sessions.

Decider handles repeated choices without generating prose. Box wraps installed coding agents in operating-system isolation and external policy checks, addressing the choice between approving every action and giving an agent broad access to files, commands, networks, and credentials.

According to recent reports, decider is a system-one model for fixed choices: one forward pass scores the supplied options and returns their probabilities without producing a text response. The same mechanism can select a tool, route a request, or judge whether an answer is sufficient.

The models use Gemma 4 bases, are licensed under Apache-2.0, and span E2B, E4B, 12B, 26B-A4B, and 31B sizes. Weights are available on Hugging Face, with v2 support in the open-source Decider repository.

AWS’s reported six-benchmark text average rises from 70.0 for v1 26B-A4B to 82.1 for v2 31B. At the smaller end, v2 E4B reaches 74.4, versus 62.7 for its v1 counterpart; the 31B version also scores 90.1 on image tasks and 70.2 on video tasks.

In a recent development, the gap between predicted confidence and observed accuracy also narrowed: AWS puts expected calibration error at 0.027 for v2 31B, versus 0.062 for v1 26B-A4B across the six text tests. Expected calibration error measures how closely predicted probabilities match actual correctness. Lower values make confidence scores more useful for deciding whether an agent should act, call a larger model, or ask a human.

V2’s training set contains 17.48 million decision examples, and its readout directly scores option tokens instead of using v1’s pointer head. Prefix-bidirectional attention processes shared state once in both directions; each subsequent question reads that encoded state and adds computation only for its own tokens.

Recent findings suggest that deployment options include local CUDA, Mac, or CPU serving, a real-time Amazon SageMaker AI endpoint, and AWS Lambda. The Lambda stack runs a quantized model on Arm64 CPUs with nothing running between requests.

Recent findings suggest that the production cost evidence comes from v1, not the latest models. In a November 9, 2026 account, AWS stated engineers on one of Amazon’s largest internal ticketing systems replaced Claude Sonnet 4.6 with Decider E4B to assign tickets to one of 20 categories. Average call time fell from 4,215 milliseconds with Sonnet to 897 milliseconds with Decider, while estimated cost dropped from about $22,200 to $500 per million tickets under AWS’s stated usage and list-price assumptions.

According to recent reports, the engineers limited that conclusion to high-volume tasks with a fixed set of answers. Workloads that require written explanations, revise their label catalog often, or depend on context beyond the model window may still require an LLM.

AWS reports that v2, without fine-tuning, routed customer-service and app-automation requests between Claude Haiku 5.5 and Sonnet 5.5. The routed setup retained 94% of Sonnet’s task-completion level while spending 44% as much. Here, calibrated confidence becomes an infrastructure control: it determines when a workload can avoid the more expensive model.

It has been revealed that the Box patch follows the original October 7, 2026 developer preview, which combined operating-system containment with fine-grained Dogwood policies. Developers can now start an installed agent with a command such as box run claude; Claude Code, Codex, and Kiro CLI retain their usual interfaces while Box enforces the selected profile’s boundaries.

It has been revealed that enforcement happens outside the model: shell activity, filesystem operations, outbound requests, and Model Context Protocol (MCP) calls are evaluated against the profile’s Dogwood rules. Those rules can identify individual files, commands, hosts, or tools and can depend on earlier session activity. An AWS example rejects the 61st AWS MCP call within an hour. Since policy decisions sit outside the model, content the agent reads cannot revise the answer, and the agent cannot alter its own rules.

Recent findings suggest that profiles combine packs, policies, and settings into task-specific personas, while packs configure agents, model providers, and tools. Separate profiles keep sessions and memory apart, and policy edits can be applied without restarting a session.

Sources indicate that routed secrets never enter the agent’s environment in usable form. It handles a placeholder; after policy permits an outbound request, Box’s egress gateway substitutes the actual credential. Keys stored where the agent can already read them, including project files and MCP configuration, receive no such protection and should be moved into routes.

Box CLI remains in preview and runs on Apple silicon Macs with macOS 15 or later and on Linux ARM64 and x86-64.

Sources indicate that the releases divide agent overhead into two control points: Decider can reduce how often expensive inference is needed for fixed choices, while Box limits the systems and secrets an unattended agent can reach. The open question for both is broader work: whether v2 can reproduce v1’s production economics outside a closed-choice workload, and whether Box’s policies can contain less predictable sessions without restoring manual approvals.
