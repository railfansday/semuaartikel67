Tabernetes: A Kubernetes cluster whose nodes are browser tabs

🌐 Source: Tabernet • 📅 27 Nov 2026 • ⏱️ 2 min read (426 words, 📖 Standard)

📑 Quick Jump: 1. Overview • 2. Key Details • 3. Closing Notes

Open the page and your phone is a node. The scheduler sends it a pod, and the pod's program runs on a Linux kernel booted in the tab. Close the tab and the node is gone, and Kubernetes starts the pod on someone else's.

Scan to become a node, or use the browser you are reading this in.

Joining downloads about 5 MB and runs a small Linux guest in the tab, on one core, until you close the tab.

The control plane in the middle, a node for each tab, and each Service on the way to the pods behind it. A node is filled when its pod is running. An orange dot is a request you sent, on its way to the pod that answered, and a green one is a tile of the picture on its way to the node that rendered it.

In a recent development, how long a tab takes to start its pod: from the tab being handed the pod to the pod's program running, which is the page loading, the kernel booting and the image being mounted. The last 0 starts.

According to recent reports, how long the cluster takes to answer: from the agent handing a request to the Service to the answer being back from a pod in someone's tab, timed on the cluster's machine. The last 0 requests, from every visitor, by the milliseconds each took.

No request has been answered yet.

Send a request to a Service. One of the pods behind it answers, on whoever's phone that is, and counts the visit in a Redis on someone else's.

Recent findings suggest that press the button and the cluster draws a Mandelbrot set. The picture is split into 64 tiles, and each node's pod computes its share in awk, on the Linux in its tab. Point at a tile to see which device drew it.

One picture at a time, for everyone.
