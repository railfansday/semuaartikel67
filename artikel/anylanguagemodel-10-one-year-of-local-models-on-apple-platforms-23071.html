📑 Quick Jump: 1. Overview • 2. Key Details • 3. Closing Notes

In a recent development, last November, we introduced AnyLanguageModel on this blog: a drop-in replacement for Apple's Foundation Models framework that lets you choose the model and provider your app uses. We heard from app developers who were curious about local models but weren't always sure how to get started. They also wanted to avoid the added complexity of supporting multiple inference providers. AnyLanguageModel grew out of that feedback.

Sources indicate that local and hosted inference each have their strengths, and both have a role in building this newly introduced generation of intelligent apps. A shared API makes it easier to choose the right model for each task.

A year and dozens of releases later, AnyLanguageModel 1.0 is out, along with swift-huggingface 1.0 and swift-xet 1.0.

Hosted providers get the same features as local models: guided generation, tool calling with streaming, and token usage on responses.

Industry observers note that reasoning is now part of the transcript too. When you switch providers, reasoning blocks are automatically omitted from requests if the latest provider can't replay them.

API keys come from a closure instead of a string, so your app can fetch short-lived tokens from your own server. The README explains when to let people bring their own keys and when to route requests through a proxy.

AnyLanguageModel also runs on Linux, so the same code can work on a server.

Sources indicate that community feedback and contributions have shaped several of our major features. Thank you to everyone who contributed for helping make AnyLanguageModel more useful to app developers.

It has been revealed that language models have proven to be a powerful tool for building intelligence into products. They're also one of many kinds of models developers can put to work.
