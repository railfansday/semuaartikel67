📑 Quick Jump: 1. Overview • 2. Key Details • 3. Closing Notes

Recent findings suggest that reply.io has announced Jason Harness, an open-source tool that turns general-purpose AI agents into a workspace for sales outreach. Announced publicly on November 17, the alpha release gives tools such as Claude Code or OpenAI Codex distinct roles for researching prospects, planning follow-ups and drafting messages. The tool keeps campaign state on the operator’s computer and leaves delivery to an external sending service. Reply claims a person must approve messages before they go out.

It has been revealed that jason Harness is separate from Reply’s managed Jason AI sales development representative. It does not ship with its own model. Instead, it packages the instructions, campaign records and approval steps that an existing agent needs to pick up a campaign across sessions. Reply’s changelog dates the opening of the complete runtime source to November 1, ahead of the broader public launch.

Recent findings suggest that reply describes nine roles covering campaign management, planning, research, writing, personalization, critique, response handling, analytics and deliverability. That designation does not necessarily mean nine different models are running. The roles define distinct jobs for the host agent. A planner can propose a sequence, a researcher can gather context, and a critic can flag an unsupported claim before a draft goes to a human reviewer.

Sources indicate that keeping campaign state outside the chat addresses a practical limitation of general-purpose assistants. A seller who starts a fresh conversation still needs to know which pitch a prospect saw, what the prospect said in response and whether a colleague already approved a follow-up. Reply describes storing campaigns, contacts and history in a local database, with rules and memory in local files. The code for the runtime and its extension system is available under the MIT license, according to Reply’s open-source documentation.

Local storage does not mean everything runs offline. The underlying agent processes requests according to its own provider and strategy. Sending takes place through Reply or another provider connected through an extension, and connected services may receive the data they need to perform a task. Any organization evaluating the alpha would need to trace what goes to each service rather than treating a locally stored database as a blanket privacy guarantee.

Recent findings suggest that moving drafting and research into the same workspace may reduce context switching. It does not remove the cost of reviewing what the AI produces. A message can sound specific while relying on an outdated job title or an unsupported claim about the recipient’s tech giant. The reviewer also needs to know whether someone opted out, whether the proposed follow-up repeats an earlier touch and whether the send still fits the original campaign brief. An approval step is more useful when it makes those facts visible alongside the draft.

The open-source release makes it possible to inspect and adapt the tool, but free access to the code is not the same as free outreach. AI subscriptions may have usage limits, and sending accounts or prospect data can carry separate costs. Reply has described the product as an alpha; its launch material does not provide independently validated results for deliverability, qualified replies or meetings compared with a conventional workflow.

The clearest test is whether the harness can reduce time spent reconstructing campaign context without increasing the time needed to correct it. Teams comparing the tool with an existing workflow could look at review time per message, how often drafts are rejected for inaccurate claims and whether replies are passed back to the right person. Those measures would say more about the tool’s value than the number of roles it can assign.
