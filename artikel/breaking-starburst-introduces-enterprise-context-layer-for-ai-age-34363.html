Starburst Data introduced its Enterprise Context Layer at Launch Point 2026 on November 18, 2026, presenting Context Studio and AI-ready Data Products as a way to give AI agents governed business meaning alongside access to distributed enterprise data.

Sources indicate that starburst says the latest advances to AIDA, its AI Data Assistant, expand the questions agents can answer, the data they can access and the workflows they support, while customers’ own agents can use the same governed context. The intended result is more accurate, consistent and traceable answers from distributed enterprise data.

Enterprise schemas locate and describe data without reliably encoding the rules behind a business question. A case record marked as pending may or may not count as open, and a column name cannot explain how net exposure is calculated or who qualifies as an active customer. Starburst’s Context Studio documentation claims this leaves agents to infer meaning that may be scattered across data products, code repositories, metadata stores, unstructured sources and analysts’ knowledge, producing different answers to the same question.

It has been revealed that context Studio consolidates glossary terms, metrics, business rules, synonyms, join keys and data products into one governed store. Its Context Studio as Code API receives context from repositories and pipelines, while an out-of-the-box Galaxy harvester derives entities from existing Starburst Galaxy data products and query history. The store tracks each entity’s origin. Because every source push describes that connection’s complete current state, an entity omitted from a later push is removed from the store.

Sources indicate that A named steward can review and certify entries through the Context Studio interface or certification API, and agents prioritize certified context. During private preview, however, all context enters as certified while Starburst develops that capability further. AIDA, Claude and other agents supporting Model Context Protocol (MCP), a standard for connecting AI applications to Galaxy data, can use the Context Studio MCP server. They apply certified definitions, metrics, rules and join keys when writing and running queries, with Starburst Galaxy applying the individual user’s access policy each time.

Recent findings suggest that the Launch Point announcement is broader than a first release of Context Studio. Starburst Galaxy’s release notes date private-preview support to October 5, 2026, listing the Galaxy harvester, Context Studio as Code API and MCP access to certified context. The newer development is the Enterprise Context Layer umbrella and the introduction of AI-ready Data Products within it, not the start of Context Studio availability.

In a recent development, context Studio remains in private preview. Organizations need a Galaxy account enrolled in the preview, administrator access to that account and access to the agent or AI client they plan to connect. Starburst requires interested customers to contact their account team for access and current preview status. Usage limits are disclosed during onboarding and may change.

Industry observers note that for enterprises running several agents, the design centralizes business vocabulary and query logic while preserving user-level data controls. The key execution issue is the certification workflow: shared context can already be distributed across MCP clients, but the preview marks every item as certified, leaving steward-controlled review as a central piece still under development.
