Industry observers note that as it turned out, the Apache DataSketches community was interested in an official Rust port. In a recent development, anyone who has implemented streaming distinct counting knows how HLL works: elements are hashed into KKK buckets, and each bucket keeps only the maximum leading-zero count seen so far (typically 4 to 6 bits), while every other hit in that bucket goes unrecorded. Once HLL enters dense mode, every bucket maintains a fixed-width register.

In a recent development, in his 2017 paper Back to the Future: an Even More Nearly Optimal Cardinality Estimation Algorithm, Yahoo! Research scientist Kevin J. Lang proposed going back to basics: instead of keeping only per-bucket maxima, retain the full KÃ64K \times 64KÃ64 bit matrix of the classic FM85 coupon collectorâs process. Whenever row rrr sees a hash with ccc leading zeros, set bit (r,c)(r, c)(r,c) to 111. Keeping the full two-dimensional hit matrix lets CPC pair a streaming HIP estimator with a mergeable ICON estimator for higher statistical efficiency than HLL. On serialization, it adapts its layout to fill density: low cardinalities use a sparse PairTable of (row, column) pairs, while medium and high cardinalities combine a sliding 8-bit window, length-limited Huffman coding, and column permutations to pack the sketch near the information-theoretic entropy limit. According to the DataSketches documentation, serialized CPC shrinks storage by 30% to 40% compared with HLL at equal accuracy.

Writing those unit tests underscored an vital engineering lesson: never write tautological tests. An earlier draft verified the asymptotic constant against a second hardcoded copy inside the test file, and checked confidence bounds only by testing whether they bracketed the point estimate.
