In a recent development, the bug is reachable from the following frameworks in their default configuration. Other frameworks are not exposed by default, but application code that upcases strings received in a legacy encoding may also be vulnerable.

Industry observers note that these products bundle their own Ruby, so the fix has to come from the vendor. Products marked Vulnerable have no fixed release yet: every current version is vulnerable.

Updated 20 November 2026 at 23:29 UTC.

Upgrade Ruby to a fixed release: 3.3.14, 3.4.13 or 4.0.10.

Recent findings suggest that install the vendor's fixed release. See Self-hosted software for fixed versions of popular products.

In a recent development, the output buffer is allocated as the input length plus 20 bytes. Each Ã adds one byte to the output, so an input with 21 of them overflows the buffer by one byte.

Recent findings suggest that the same loop is in several ISO-8859 and Windows-125x encodings and has been there since Ruby 2.4.0. It is reached by upcase, swapcase, downcase(:fold) and casecmp?.

UTF-8 strings take a different code path and are not affected.

Fixed upstream in ruby/ruby@d582f8f.

A one-byte heap overflow. The byte written is S (0x53) when upcasing or s (0x73) when case-folding, and it lands directly after the output buffer. The attacker controls the size of the buffer through the input length.

Copying the result out of the buffer then reads one byte out of bounds.

We'll be publishing a proof of concept demonstrating remote code execution on stock Rails on 25 November 2026, or later if major vendors have not shipped a fix by then.

Veria Labs found this vulnerability independently and was the first to demonstrate remote code execution.

In a recent development, the Ruby security advisory also credits Stephan Lipp (Ada Logics) and Anthropic with reporting the underlying primitive. Additional discoverers include Moritz Sanft in collaboration with OpenAI.
