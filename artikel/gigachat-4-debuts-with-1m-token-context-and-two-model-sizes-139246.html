According to recent reports, the GigaChat Team revealed GigaChat 4 on November 26, 2026, releasing 708B- and 37B-parameter mixture-of-experts models with native one-million-token context windows. Both activate only a subset of their parameters per token, support tool calling and multi-step agent tasks, and allow Instant or Reasoning responses to be selected per request within one checkpoint.

The flagship 708B-A41B uses approximately 41B active parameters per token, compared with roughly 3.8B for the compact 37B-A4B. Both were trained on sequences extending to the full context length for work with long documents, collections of sources and large codebases. This arrangement replaces GigaChat 3.5’s separate instant and reasoning checkpoints.

Both models use a 3:1 mix of Gated DeltaNet layers and multi-head latent attention layers enhanced with DeepSeek Sparse Attention (DSA). Gated DeltaNet maintains a fixed-size recurrent state, while DSA selects up to 2,048 earlier positions for each query rather than computing attention over the entire sequence. The companion technical report says indexer and selection overhead can outweigh the attention savings at short contexts or small decode batches.

Recent findings suggest that the flagship has 64 decoder layers and 256 routed experts, selecting eight per token together with one shared expert. The compact model has 32 layers and 192 routed experts, using the same combination of eight routed experts and one shared expert.

For the 708B model, context extension progressed from 32K to 128K tokens before indexer training and joint optimization at the native length. After supervised fine-tuning, specialist models underwent reinforcement learning in mathematics, coding, tool use and multi-turn agent workflows. Multi-teacher on-policy distillation then consolidated their capabilities into one model offering both response modes.

Recent findings suggest that under the team’s evaluation protocol, the 708B model scored 71.26% on Terminal-Bench 2.0 in Reasoning mode and 60.47% in Instant mode, versus 30.30% and 12.94% respectively for GigaChat 3.5. Its reported Reasoning results also include 80.89% on SWE-bench Verified and 79.55% on BFCL v4, although GLM-5.3 is listed higher at 86.67% on SWE-bench Verified.

The compact model’s reported Reasoning results include 85.00% on LiveCodeBench v6, 70.80% on SWE-bench Verified and 72.00% on BFCL. For the flagship, evaluation combined public runners and scoring code with the team’s own implementations, including seven-hour timeouts for specified agentic benchmarks.

The team’s demonstrations emphasize tasks that chain artifacts and tools: the flagship modified a Mario cartridge’s palette in its binary file and ran the game on a Mac M4, produced an STL vase for 3D printing, and used MCP access to the Cadenza music workstation to compose a track before building an accompanying visualization site.

The flagship model card lists FP8, BF16 and GGUF instruction-tuned variants, along with base and intermediate checkpoints, and releases its instruction-tuned checkpoint under the MIT License. The compact model card lists the same variant categories but uses the Noncommercial License for Individuals 1.0. The detailed technical report currently covers the 708B model; a dedicated report for the 37B model is planned for later.

According to recent reports, both cards document SGLang and vLLM serving, per-request mode selection and OpenAI-compatible tool calling. They recommend Pi for agentic tasks, with Codex CLI and DeepSeek Harness as alternatives for interactive terminal work.

The flagship’s documented FP8 configuration uses two nodes with eight H100 80 GB GPUs each. The compact model’s example uses one H100 80 GB GPU, with approximately 40 GB required for its weights before attention caches, recurrent states and activations.

Sources indicate that gigaChat 4 makes deployment terms part of the model choice alongside benchmark scores: the flagship combines MIT licensing with a two-node example, while the compact model offers a single-GPU path under noncommercial terms. For prospective people, the compact checkpoint’s usage restrictions are therefore as consequential as its lower hardware requirement.
