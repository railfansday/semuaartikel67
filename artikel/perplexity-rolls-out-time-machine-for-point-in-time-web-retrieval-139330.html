Perplexity Rolls out Time Machine for Point-in-Time Web Retrieval

📑 Quick Jump: 1. Overview • 2. Key Details • 3. Closing Notes

Perplexity revealed Time Machine on November 25, 2026 for its Search API and Context API, allowing developers and agents to search and read the web through copies saved at or before a chosen timestamp. At launch, historical cutoffs reach back as far as 365 days.

According to recent reports, the new snapshot_as_of parameter is intended for evaluations and other work where later information would distort the result. A team can present an agent with a question as it stood at an earlier point, grade the answer against the subsequent outcome, and test whether a model, prompt or retrieval setup improved performance.

Perplexity’s crawler creates a dated archive: every crawl stores a page copy and its capture time, giving each URL a sequence of versions. For a historical Search request, eligibility is limited to pages published or first crawled by the cutoff. Each candidate is replaced by its newest archived version no later than that timestamp, and ranking evaluates the older text. The title, date and snippet come from that version too.

Industry observers note that the same timestamp can be passed to the Context API for full-text reads, keeping search and page retrieval on one historical view. Omitting the parameter leaves the request on the current web rather than a historical view.

The Search API documentation requires a timestamp in the RFC 3339 format with a time zone, and rejects future cutoffs or requests outside the historical window. Domain and language filters remain available; search_recency_filter, publication-date and last-updated filters, and People Search do not work with the cutoff. Historical responses omit last_updated. Pages that cannot be shown at that time are dropped, so a search may return fewer than the requested max_results count, or none.

According to recent reports, the Context API documentation indicates historical reads never fetch live pages. For successful reads, metadata.origin is cached, and metadata.fetched_at records when the copy was obtained. Markdown, query highlights and yes/no criteria scoring are available, while HTML and links are not. A URL returns no_content when there is no copy at or before the cutoff, when the page returned 404 or 410 then, or when the stored copy is unreadable. The cutoff also cannot be combined with the age, cache-only or conditional-request controls: max_age_seconds, cache_only and if_modified_since.

It has been revealed that beyond benchmarking, Perplexity describes reinforcement-learning training, prediction-market evaluation, finance backtests, agent replay and debugging, and historical checks of pricing pages, terms of service and changelogs. Finance tests can place the cutoff hours before an earnings call, FOMC announcement or acquisition; audit work can read the same URL at two timestamps. The common requirement is that later outcomes must not inform the answer being measured.

Perplexity reports that it used reinforcement learning to train GLM-5.3 Flash on resolved 2026 political questions listed on Polymarket. Search was limited to information available when each question was asked, and forecasts were graded against actual outcomes. Before training, the model scored 0.94 on held-out questions with live-web access, versus 0.77 with Time Machine; the Polymarket price on the question date scored 0.79 under the same method.

In a recent development, perplexity trained the model once with live-web access and once with Time Machine, then scored both on the same held-out questions with Time Machine enabled. It reports that about 90% of live-web training groups had zero gradient, meaning no useful learning signal, because outcome lookups produced identical forecasts and scores; the comparable share was about 25% with Time Machine. The Time Machine-trained model’s held-out reward rose from the earlier baseline to 0.80, above the market score. The contrast reveals how answer leakage can flatter a forecasting evaluation: retrieving the published outcome is different from predicting it.

Perplexity’s comparison used three sets of 1,000 queries: a random sample of Time Machine queries, news queries and prediction-market research queries, with the same queries and cutoffs run against Exa Snapshot. It reports publication dates on 98.8% to 99.5% of returned Time Machine pages across the sets, compared with 66.1% to 77.7% for Exa.

Perplexity says its automated judge then read the returned pages for information from after each cutoff. The largest gap was in the random sample: 0.25% of Time Machine pages were flagged, versus 1.10% of Exa pages, and 18 Time Machine queries and 62 Exa queries returned at least one flagged page. The gaps were smaller for news and prediction-market queries.

Time Machine is priced at $5 per 1,000 Search API requests and $1 per 1,000 Context API URLs fetched, with no surcharge for historical requests. It works with an existing API key and has a default rate limit; Perplexity directs customers seeking higher limits to its API team.

No new endpoint or setup is required, so existing customers can add the cutoff to current workflows. The result is a common retrieval layer for live work, historical evaluation and audits: teams gain a fixed evidence set for measuring agents and reviewing past pages, while archive coverage becomes part of the evaluation design.
