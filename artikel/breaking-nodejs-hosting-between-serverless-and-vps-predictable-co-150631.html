It has been revealed that the first sign of trouble is rarely a crash. It is the invoice.

Recent findings suggest that A small team ships a Node.js app on a serverless platform because it is quick to set up. Traffic grows, and the bill grows with it, in ways that are hard to forecast. Some visitors also wait a beat longer for their first response, because the function has to start up before it can answer.

The usual alternative is a virtual private server (VPS). The price is fixed, but the work is not. Someone has to patch the operating system (OS), configure the web server, renew SSL certificates and keep backups running.

Recent findings suggest that between the two sits a third option: managed hosting for Node.js. Here is how the three compare, and how to choose.

According to recent reports, platforms such as AWS Lambda charge for what runs. Lambda's event functions are priced on the number of requests and on duration, measured in GB-seconds, and the memory you choose sets the CPU and the cost per second.

That suits small or spiky workloads. A newly introduced app with little traffic can sit inside the free tier, which covers one million requests and 400,000 GB-seconds a month.

The surprises come with growth. Billed duration is multiplied by the number of requests, so even small inefficiencies in a handler can turn into significant costs at scale.

Then there is the cold start. When the platform has to create a newly introduced execution environment, the first request waits. AWS's own decision guide puts Lambda cold starts at roughly 100 milliseconds to over 1 second.

Since August 2025, AWS bills for that initialization (INIT) phase across all function configurations, so a cold start now reveals up on the invoice as well as in the response time.

Sources indicate that AWS's own analysis found they occur in under 1% of invocations, so steady traffic makes them far less. For a checkout page that does hit one, it is still a pause the customer feels.

There are fixes. Provisioned concurrency keeps functions initialized and ready, but it is billed for the time it is enabled. Newer options let one execution environment handle several requests at once, which means fewer cold starts.

Sources indicate that limits matter, too. A Lambda function can run for 15 minutes at most, and accounts start with a default of 1,000 concurrent executions. Long-running jobs need a different home.

A VPS fixes the pricing problem. A plan costs the same every month, whatever traffic does.

On an unmanaged VPS, the team owns everything above the hardware. That means operating system updates, a firewall, a web server such as NGINX in front of the app, a process manager such as PM2 to restart it if it crashes, SSL certificate renewals and backups that someone has to test.

Sources indicate that none of it is exotic. All of it is a job. Left undone, it is how small teams end up with unpatched servers and no way to restore one.

For a team without a sysadmin, the real price of a VPS is the hours.

Managed Node.js hosting sits between the two. The app runs on a persistent infrastructure, so there is no scale-to-zero and no cold start between requests. The price is a flat monthly initiative. The provider handles the work around it.

Recent findings suggest that the trade-off is scaling. Velocity scales vertically: you pick a server size and move up when the app outgrows it. A traffic spike beyond that server's capacity is a capacity problem, not something the platform absorbs by adding instances.

Sources indicate that look at the traffic first. If it comes in bursts with long quiet gaps, serverless often wins. If it is steady, a server is usually simpler to reason about.
