📑 Quick Jump: 1. Overview • 2. Key Details • 3. Closing Notes

Most x402 tutorials start with "create a wallet and fund it". That is a lot to ask before you know whether anything useful is on the other side. This one starts with nothing: no wallet, no keys, no funds. Your agent reads live sellers and real prices, and it cannot pay anything.

Other MCP clients: command npx, args ["-y", "@agent402-dev/pay-mcp"], the same env.

Without X402_KEYPAIR_PATH there is no wallet, and without X402_TRUSTED_PAY_TO every payment is refused before signing.

"Run bond_find_sellers." It reads an open directory of job URLs and each seller's live terms: price, seller bond, buyer deposit, delivery time, review window. For each seller it also notes which of your settings would refuse the deal. Today the directory lists two small sellers run by the toolkit developer (Solana transaction receipts and wallet activity CSV), marked as developer-run.

"Run x402_quote on https://agent402-tx-receipts.agent402-ebc.workers.dev/x402/receipts?signatures=". The server answers HTTP 402 with its price (0.05 USDC). pay-mcp shows it and answers refused, because no recipient is trusted yet. Nothing is signed.

According to recent reports, create a small wallet just for the agent (npx -y @agent402-dev/pay-mcp init), fund it with a few USDC, and add the recipient and limits you choose. Bonded jobs (the seller locks a bond, you lock a deposit, you accept after checking a hash of the result) use the bond_v2_* tools. The Bond v2 program has no upgrade authority; it was reviewed internally and is not independently audited.
