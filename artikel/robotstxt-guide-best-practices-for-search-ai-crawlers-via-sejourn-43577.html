According to recent reports, the robots.txt file has always been an essential tool for managing crawler access to a website. With AI search tools and agents now visiting websites alongside traditional crawlers, you need to know which rules each one follows.

It has been revealed that but, blocking the wrong bot can exclude your content from LLMs or SERPs, while leaving unnecessary URLs open can waste crawl budget on large sites. So, you need to know what you are doing.

This guide will help you understand how robots.txt rules work so you can avoid common robots.txt mistakes, keep useful content accessible, but at the same time limit unnecessary crawling.

The robots.txt is a simple text file that sits in the root directory of your site and tells crawlers what should be crawled.

Google’s 2024 reminder about action URLs focused on add-to-cart and wishlist links that waste crawler and server resources.

According to recent reports, imagine you have an online store with hundreds of thousands of pages. There are sections of websites like filtered pages that may have an infinite number of versions. Those pages don’t have unique value, essentially contain duplicate content, and may create infinite crawl space, thus wasting your server and Googlebot’s resources. That is where robots.txt comes in, preventing search engine bots from crawling those pages.

If you don’t do that, Google may try to crawl an infinite number of URLs with different (even non-existent) search parameter values, causing spikes and a waste of crawl budget.

As a general rule, you should always ask why certain pages exist, and whether they have any value for search engines to crawl and index.

Industry observers note that you can block training bots while allowing AI tools to find your pages and retrieve them for owners. The key is to give training, search, and user-requested AI crawlers separate rules.

Publishers may block training to limit the use of their reporting without attribution, while ecommerce brands may welcome it if product mentions lead people to search and buy. Because the benefits differ by business, developers should set these rules with stakeholders.

It has been revealed that disallowing training bots cannot guarantee that your content stays out of training datasets, because crawlers that ignore robots.txt can still collect it. It also does not force AI tools to visit or cite your site, as they may find the information elsewhere.

It has been revealed that A BuzzStream study covered by SEJ in January 2026, found that 79% of the US and UK news sites examined disallowed at least one training bot, while 71% disallowed at least one retrieval or live-search bot. Because retrieval helps AI tools find and cite your pages, blocking those bots is a separate decision from opting out of training.

Including your sitemap URL in the robots.txt file helps search engines easily discover all the important pages on your website. This is done by adding a specific line that points to your sitemap location, and you can specify multiple sitemaps, each on its own line.

Unlike Allow or Disallow rules, which allow only a relative path, the Sitemap directive requires a full, absolute URL to indicate the location of the sitemap.

Ensure the sitemaps’ URLs are accessible to search engines and have proper syntax to avoid errors.

It has been revealed that the crawl-delay directive in robots.txt specifies the number of seconds a bot should wait before crawling the next page. While Googlebot does not recognize the crawl-delay directive, other bots may respect it.

It helps prevent server overload by controlling how frequently bots crawl your site.

Sources indicate that robots.txt rules apply to the host, protocol, and port where the file is requested. If you need crawl restrictions on a subdomain, its robots.txt URL must serve the rules or redirect to a file that does; the parent domain’s file is not inherited.

It creates challenges when you have a website with a dozen subdomains, as it means you should maintain a bunch of robots.txt files separately.

However, it is possible to host a robots.txt file on a subdomain, such as https://cdn.example.com/robots.txt, and set up a redirect from https://www.example.com/robots.txt to it.

You can do vice versa and host it only under the root domain and redirect from subdomains to the root.

According to recent reports, google applies the retrieved rules to the host that originally requested robots.txt, not automatically to the host storing the shared file. Configure a redirect from each host you want to manage, and check that the shared paths make sense for all of them.

It helps make updates and maintenance more efficient. Otherwise, you would need to use a separate robots.txt file for each subdomain.

A properly optimized robots.txt file is crucial for managing a website’s crawl budget. It ensures that search engines like Googlebot spend their time on valuable pages rather than wasting resources on unnecessary ones.

It has been revealed that blocking compliant crawlers can reduce unwanted requests. For AI systems, distinguish crawl restrictions from training-use controls, and verify the effect in your logs. Google-Extended and Applebot-Extended do not stop a separate crawler.

Make sure you always validate your changes to avoid unexpected crawlability concerns.

In a recent development, however, remember that crawl demand and serving capacity both matter. Useful content, efficient page loading, and a healthy server remain important alongside robots.txt rules.
