Sources indicate that I like making little tools that do one thing well and thing finding clever ways to combine them. It's the ethos behind a lot of the little software projects I have over at Less Software.

One of the first ones I made was a tool called whereami. Tongue-in-cheekly, I wanted to pitch it as the natural compliment to whoami. For that tool, the thinking was nearly every modern OS provides some kind of native API for geolocation. It felt silly to me that I could run a quick command from the terminal for so many things, but I couldn't run one that taps into this capability.

It has been revealed that in the pursuit to make that tool cross-platform, one of the things I found myself navigating were the differences between them. Consistently, macOS tended to have a lot of extra niceties baked in, particuarly when it came to imagine recognition, natural language processing and accessibility tooling.

Sources indicate that looking up an address doesn't need location permission, because nothing is asking where you are. jq does the arithmetic. The -s flag slurps both JSON objects into an array, and the filter averages the coordinates:.

According to recent reports, nearme searches for places around a set of coordinates using MapKit, the search engine behind Apple Maps. It reads coordinates from JSON on stdin, and it only cares about latitude and longitude. It has no idea those numbers came out of jq and not out of a GPS.

In a recent development, averaging two coordinates is not the "real" way to find the middle, but over a few miles trying to find a place to meet for coffee it's close enough. What does matter is that the midpoint has no idea what's actually there.
