In a recent development, messages sorted by: [ date ] [ thread ] [ subject ] [ author ] Hello! We are pleased to announce the availability of a latest GPGME release: version 2.3.1. This version fixes a *critical security bug* found in all prior versions. We also release a new Gpg4win versions and and GnuPG Desktop and GnuPG VS-Desktop versions which all make use of GPGME. Description =========== By using an OpenPGP key containing a crafted very long user id it is possible to trigger a double free. This double free can be used exfiltrate data from applications by sending for example signed data. Exploiting this bug to mount an Remote Code Execution attack (RCE) can't be ruled out. Thus an immediate revision is highly suggested. Our internal ID is T8557 (https://static.dev.gnupg.org/T8557) The CVE-id is CVE-2026-129975. This vulnerability was discovered by Johan Carlsson and we were informed by GitLab on 2026-11-12. Initially we set 2026-11-25 for a coordinated disclosure; due to the new Ruby2Shell bug GitLab had to update earlier and thus we also disclosed the GPGME bug on 2026-11-20. The root cause for this bug are two GPGME internal functions to read the status lines and key listings from gpg. Initially a buffer of 1024 bytes is allocated which is reallocated if more space is required. When reallocating the pointer to the new buffer is used by the function but it is only assigned back to the context object at the end of the function. Thus if the function returns early due to an read error or other events the context is not updated and keeps the stale pointer to the freed memory. Eventually the context is released and the memory freed a second time. Due to other allocations in between the common double free checks of memory allocators may not be triggered. Impact ====== All software using a GPGME version prior to 2.3.0 either as shared libary, DLL, or statically linked is affected. Examples of software using GPGME are - Gpg4win - GnuPG Desktop - GnuPG VS-Desktop - Most mail clients - Many XMPP clients - Samba - Flatpack Solution ======== Please update your GPGME shared library to version 2.3.1. If you need a DLL you may take it from from the updated Gpg4win version. For statically linked binaries remmeber to build them against GPGME 2.3.1. If for some reasons GPGME can't be updated, you may patch your GPGME version using the attached patch which likley applies cleanly even to very old versions. There is no need to udpate GPGMEPP or GPGMEQT.
