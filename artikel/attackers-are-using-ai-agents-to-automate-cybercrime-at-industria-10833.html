Attackers are using AI agents to automate cybercrime at 'industrial scale,' FBI and AWS warn

Critical orgs around the globe under seige.

Attackers are using open source AI penetration testing framework ARTEX to automate their attacks on banks, governments, energy and healthcare providers, and other critical sectors around the globe, according to security alerts from the FBI and Amazon Threat Intelligence.

Between October 3 and November 5, Amazon’s MadPot honeypot threat sensors detected two ARTEX campaigns: one that allowed thieves to steal AI credentials at “industrial scale” to gain free access to models, and a second that generated deepfake videos to trick live selfie checks.

In the first one, miscreants used AI agents to steal API keys, and then feed these keys into the ARTEX framework’s model gateway to power more agents searching for more AI model access keys.

“Agents validated identities through each provider’s token and identity services, enumerated storage, assessed permission scope, and went after managed AI model services, secrets and parameter stores, and application identities,” AWS Chief Information Security Officer CJ Moses wrote in a blog post on Friday.

Targets included LLM gateways and proxy platforms such as One API, Latest API, Veloera, Sub2API, and LiteLLM, and AI application builders Dify, FastGPT, Langflow, RAGFlow, Open WebUI, LobeChat, and Ollama.

This campaign also used cloud credentials to gain stolen access to the models.

In a second campaign, attackers used ARTEX to create real-time deepfake videos to trick identity verification (KYC) checks at two cryptocurrency exchanges, and forged ID photos to pass document checks.

“The agents reverse-engineered one vendor’s liveness protocol in detail, documenting the face-detection event stream it sends, how it tracks face position during the check, and the coordinate system it uses to tell the user where to move,” Moses wrote.

The agents did manage to complete the full movement sequence with the face positioned within 7 pixels of the target, but this feat was not enough, as the vendor’s server-side verdict rejected the deepfake in every attempt.

In a separate session, agents built a real-time deepfake video pipeline on a single consumer-grade GPU using an open-source face animation model. This video achieved 11.5 frames per second, which Moses remarked is “close to what a live video check expects.”.

Meanwhile, agents also worked on the ID document checks, building synthetic camera metadata whose image dimensions matched the real values inside the JPEG file, and preserving the original camera compression tables that are usually replaced by re-saving an edited image.

Sources indicate that while the end goal was stealing cryptocurrency, the campaign illustrates how ARTEX runs several sessions simultaneously, with multiple agents working toward the same result. “One searched for ways to cash out, one worked on clearing account balances, one set up the deepfake video pipeline, and one carried out the verification bypass,” Moses wrote.

None of the attack techniques are latest, but both of these campaigns show how AI agents can boost the speed and persistence of the attacker.

Recent findings suggest that “The agents succeeded where basic security hygiene was missing, including default or hardcoded credentials, keys left in code and public artifacts, unauthenticated interfaces and inference endpoints, and unpatched software,” Moses added. “Getting those fundamentals right remains the most effective defense.”.

The FBI also hammered this message in a separate Friday alert noting “ARTEX significantly reduces the time required to chain attack techniques, with some intrusions progressing from initial targeting to privileged access in under three hours.”.

Industry observers note that the federal cops cited the August attacks against South Korean financial institutions that stole personal data belonging to about 67,000 people. The FBI also highlighted a September ARTEX campaign that targetedd ConnectWise Cloud Backup customers in a supply chain attack that ultimately compromised more than 2,250 downstream Microsoft tenants.

After these security breaches became public, the original ARTEX developer removed the GitHub repository in October.

According to recent reports, however, forked and localized variations plus a commercial version remain, and as of November 4 internet scanning service Censys identified 1,465 hosts running an exposed ARTEX console. And the total number of deploymentsis “likely significantly higher when including systems behind firewalls or in private networks,” according to the FBI.

The feds urged all organizations – especially those operating internet-exposed applications, self-service portals, cloud infrastructure, and partner or supplier systems – to implement a series of mitigation measures outlined in its Flash alert.

These include reducing external attack surfaces by restricting sensitive services to trusted networks, private connectivity, or dedicated administrative paths, and moving enterprise applications behind zero-trust access policies and permissions. ®.
