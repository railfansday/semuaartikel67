go-intl is a high-performance internationalization library with a simpler API. It should be the definitive answer to internationalization in Go.

I decided to write go-intl while I was building the terminal and desktop clients for a personal agent entirely in Go. When I needed to add internationalization, I took one look at go-i18n’s API and knew it wasn’t what I wanted. I wanted something simpler, so I decided to build a new library with better performance and a simpler API.

Let’s look at the thinking behind the design.

Imagine a page with forty pieces of text to translate. Three of them are a status label, a greeting, and the number of items in a cart.

In a recent development, A message index has one job. Given a string key, it returns the message index. I wanted to know whether a sorted slice was worth using when the keys were short and the dictionary had only a dozen or so entries. With a larger dictionary, how much lookup time could a hash table built specifically for these keys save? I tested three implementations on the same keys, using a sorted slice, a custom hash table with linear probing, and a Go map. At 16, 1,024, and 16,384 keys, Go’s map was the fastest on successful lookups, both when looking up one key repeatedly and when cycling through different keys. That’s why go-intl kept map[string]int.
