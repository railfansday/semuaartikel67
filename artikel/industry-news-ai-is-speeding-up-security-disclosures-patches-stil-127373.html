📑 Quick Jump: 1. Overview • 2. Key Details • 3. Closing Notes

It has been revealed that software vendors can find and disclose more vulnerabilities with AI-assisted research, but companies that rely on those vendors still have to wait for fixes that work on their equipment. Eclypsium’s November InfraTrust Pulse report illustrates the gap. It tracked 373 advisories from 23 infrastructure vendors over 36 days, covering 3,880 distinct vulnerability identifiers. More than half the advisories in the period appeared on a single day. The report follows network equipment, servers, chips, firmware, and the controllers that let enterprises manage hardware remotely.

According to recent reports, fortinet accounted for 89 advisories that day. According to Eclypsium, 82 credited Fortinet’s product security team working with frontier AI models. The number of advisories was nearly eight times the vendor’s earlier average per release day that year. That is a striking example of how AI can assist a security team, but a single release day cannot establish how much of the increase came from AI, whether the pace will continue, or whether there are more underlying flaws. An advisory is also not the same thing as a newly discovered vulnerability: one advisory can cover several findings, and several vendors can issue advisories about the same flaw.

An infrastructure product can contain code written by its vendor alongside firmware, libraries, and other components supplied by outside companies. When the underlying component has a vulnerability, multiple manufacturers may have to determine which products include it, which versions are affected, and how to deliver a fix. Eclypsium counted 40 advisories arising from just six shared-component flaws. That helps explain why a month’s advisory totals can look much larger than the number of underlying complications that teams need to understand.

This is where a software, hardware, or firmware bill of materials can help. A conventional asset inventory tells a organization which devices it owns. A component inventory can help answer a different question: which of those devices depend on the same piece of code? Eclypsium’s supply-chain guide describes mapping those components to products. The quality of that inventory matters as much as its existence. A stale inventory, or one that does not record the version of a component in the equipment actually deployed, can still leave a security team waiting for vendor confirmation.

The report describes a case in which a component enhancement was already available in October, but projected fixes for some products extended to June 2027. For a downstream vendor, integrating a fix can mean validating it across hardware revisions, testing whether it breaks management functions, and producing firmware packages for each supported device. Customers then have their own installation and validation windows. The latest target date in the report is not a prediction for every vendor or device, but it illustrates how long the distance from upstream fix to customer deployment can be.

For defenders, the practical lesson is to track exposure and available fixes separately. A burst of AI-assisted disclosures makes it more vital to reconcile duplicate advisories and prioritize affected equipment. CISA’s Known Exploited Vulnerabilities catalog provides one input to that judgment, alongside what an organization actually runs and which fixes it can deploy. Where a fix is not yet available, teams can document what is exposed, track vendor guidance, and reassess the risk as new information arrives. Faster discovery helps, but the more consequential measure for operators is how long a known exposure remains in their own environment.
