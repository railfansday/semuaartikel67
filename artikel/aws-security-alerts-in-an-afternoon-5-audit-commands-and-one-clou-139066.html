Sources indicate that on November 28, 2025, Sysdig watched an attacker take test credentials from a public S3 bucket and have their own code running in the victim's Lambda function eight minutes later. Admin access followed in under ten.

Industry observers note that that is fast, but it is not unusual. Unit 42 leaked keys to public GitHub on purpose and saw them used within five minutes. Clutch Security measured 6.6 minutes on average.

Most of us have no security team. This post is the setup I would do in an afternoon instead:.

In a recent development, attachUserPolicy earns its place twice. It also fires when AWS quarantines a leaked key, because the quarantine is a policy attached to the user. The policy ARN is in the event's requestParameters.

Recent findings suggest that some of these are noisy on a busy account. AuthorizeSecurityGroupIngress fires for every rule, not just 0.0.0.0/0. Start with everything, then trim what your own pipeline does every day.

aws events test-event-pattern checks a pattern against a sample event without creating anything. This is how I tested the sign-in rule:.

In a recent development, I ran nine cases across the two rules. Root sign-in, IAM user without MFA, StopLogging and CreateAccessKey matched. An IAM user with MFA, a failed login, a single sign-on session and DescribeInstances did not.

It has been revealed that 1. IAM lives in us-east-1. IAM, STS and CloudFront are global services, and CloudTrail records their events in US East (N. Virginia). A rule in eu-west-1 will never see CreateAccessKey. Root sign-ins land in us-east-1, us-east-2 or us-west-2. Deploy the stack in us-east-1, then in those two, then in every Region you run workloads in.

According to recent reports, 2. MFAUsed is always No for single sign-on. AWS only sets it for IAM users and root. Without the IAMUser filter, every SSO login emails you.

3. S3 event names differ from the API. The API call DeletePublicAccessBlock appears in CloudTrail as DeleteBucketPublicAccessBlock or DeleteAccountPublicAccessBlock. Match the CloudTrail name.

4. Read-only calls need a different rule state. A rule in the default ENABLED state does not match read-only management events. To alert on something like GetSecretValue, set the rule's state to ENABLED_WITH_ALL_CLOUDTRAIL_MANAGEMENT_EVENTS. You also need a trail that is logging, or none of these rules receive anything.

One more: the docs spell the sign-in detail-type two ways (AWS Console Sign In via CloudTrail and AWS Console Signin via CloudTrail). The pattern above matches on source: aws.signin so it does not depend on either.

You now get an email at about minute five. It is a block of JSON. It does not say whether that CreateAccessKey was your deploy pipeline or a stranger, and at 3 a.m. nobody reads it until morning.

That gap is the real work. Someone has to look at who did it, from where, and what else they did in the same few minutes. Staffing that around the clock takes 4.2 people per seat (168 hours in a week, 40 in a working one), which is about $542,556 a year at the US median analyst wage.
