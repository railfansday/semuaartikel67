Industry observers note that google unveiled on November 24, 2026 that its Workspace Model Context Protocol (MCP) servers and Workspace command-line interface (CLI) are generally available, alongside rules requiring AI agents to use those interfaces instead of existing REST APIs. Technical enforcement begins February 1, 2027.

Google reports that Workspace APIs handle more than 2.8 trillion calls a month, with public Drive API traffic more than two-and-a-half times its 2022 volume. Traditional applications can continue using existing REST APIs; the fresh requirement applies to AI agents and other AI-driven tools.

Google’s rationale is that traditional REST APIs were built for human-paced applications, where a valid OAuth token implied user intent. An autonomous agent acting at machine speed across email, documents and cloud infrastructure changes that assumption. The newly introduced design puts policy checks, data boundaries and human confirmation into the request path.

Sources indicate that the Workspace servers use MCP to give AI applications a standard way to read data and take actions. Dedicated remote servers are generally available for Gmail, Drive, Docs, Sheets, Slides, Calendar, Chat and Tasks, inheriting each user’s permissions and data-governance controls. The Workspace CLI serves local agents, terminal workflows and automation, with structured JSON output and scoped OAuth sign-in across Workspace services.

Industry observers note that each agent call through these interfaces is checked against organizational permissions, data-loss-prevention rules and classification labels. The MCP servers reject OAuth clients that are not designated for AI agents, and agents connecting to Workspace must use dedicated OAuth client IDs with least-privilege scopes and usage quotas. Billing is scheduled to begin on April 1, 2027, while time-limited approvals are listed as coming soon.

According to recent reports, draft creation and document summarization can run autonomously. Sending email, changing Drive sharing permissions and making bulk edits require explicit user confirmation. Workspace administrators can view, audit and revoke agents in the admin console; user-facing activity review and revocation, plus controls to block agent access to Gmail messages and specific Drive files or folders, remain forthcoming.

Recent findings suggest that the Workspace AI Tools Addendum covers standalone agents, the software harnesses that deploy or orchestrate them, and applications or services using AI models. It bars disguising a tool to avoid classification or circumvent the Google MCP requirement. That makes the migration a compliance issue for third-party agent platforms as well as for developers building directly on Workspace.

Industry observers note that workspace user data and Google Technical Information, a category of service information obtained or derived through Workspace access points, may be processed only to fulfill active, user-authorized tasks. Neither category can be used for model training, fine-tuning, evaluation dataset construction, model distillation or developing a service similar to a Workspace service. Scraping and systematic probing beyond what an authorized task requires are also prohibited.

Recent findings suggest that google Technical Information cannot be stored for more than 30 days. Covered user data and technical information must not be retained after a tool is disconnected or its access is revoked. If Google reasonably believes those rules have been violated, it can immediately restrict or remove the tool’s access, or suspend or terminate the customer’s access to the relevant Workspace services.

It has been revealed that on Google Cloud, Agent Gateway verifies Agent Identities against the Agent Registry directory, enforces identity and access management policies and default-deny outbound rules, and screens requests with Model Armor. It governs inbound client-to-agent traffic and outbound requests from agents to tools, APIs and other agents. Custom authorization checks can be delegated to an organization’s own policy engine or third-party security tools through Service Extensions.

Cloud Run support and Agent Gateway for cross-cloud Kubernetes environments remain in Limited Preview. Each gateway instance can govern up to 5,000 resources registered in Agent Registry.

Google’s MCP configuration guide requires screening prompts and responses for indirect prompt injection, meaning hidden instructions in untrusted content, using Model Armor or a documented alternative. Malicious emails or documents could hijack a session and modify, steal or delete data. Current known issues include some English-only approval prompts, no user self-service viewing or revocation of saved tool approvals, and expiration of those approvals after 90 days.

For enterprises, agent governance is now built into the supported Workspace access path. The practical burden is the migration: existing agent integrations must satisfy the latest identity, confirmation, screening and retention rules on Google’s schedule, while parts of the user-control and deployment model remain pending.
