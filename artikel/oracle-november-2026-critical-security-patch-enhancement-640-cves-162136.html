Sources indicate that oracle's monthly Critical Security Patch Update cadence is only six months old, yet November's release reads more like a full quarterly overhaul. On November 17, 2026, Oracle published its November 2026 Critical Security Patch Update (CSPU) Advisory, delivering 655 latest security patches across 640 unique CVEs spanning 21 enterprise product families.

Industry observers note that since launching monthly CSPUs in May 2026 to bridge the gap between larger quarterly Critical Patch Updates (CPUs), Oracle has used the third Tuesday of each month to push high-priority fixes faster. According to Tenable's Research Special Operations analysis published on November 17, 62 of this month's 655 patches carry a Critical severity rating, and dozens of flaws across Java SE, Oracle APEX, Oracle REST Data Services, and Fusion Middleware are remotely exploitable over a network without authentication.

We haven't tested this ourselves; this is based on Oracle's official November 2026 CSPU advisory and Tenable's Research Special Operations breakdown.

In a recent development, when a single vendor drops 655 patches on a Tuesday afternoon, treating every product family with equal urgency slows down remediation where attackers actually aim. Breaking down the distribution immediately shows where the highest concentration of unauthenticated network exposure sits.

It has been revealed that oracle Hyperion absorbs the largest share of fixes by a wide margin, accounting for 267 patches (40.8 percent of the entire November CSPU), including 107 vulnerabilities that can be exploited remotely without credentials. Oracle Supply Chain follows with 74 patches (36 unauthenticated remote flaws), while Oracle E-Business Suite and Oracle Fusion Middleware tie at 71 patches each. Notably, 53 of Fusion Middleware's 71 patches are remotely exploitable without authentication.

At the severity level, 62 patches (9.5 percent) are Critical across 57 unique CVEs, 249 patches (38 percent) are High across 245 CVEs, 274 patches (41.8 percent) are Medium across 268 CVEs, and 70 patches are Low across 70 CVEs.

Sources indicate that among the 640 CVEs, one vulnerability already carries a nickname security teams will recognize: CVE-2026-114938, dubbed Java4Shell by researchers. Reported to Oracle by Albert Yang and Quang Luong of Calif.io, the vulnerability lives in the Compiler component of Oracle Java SE and Oracle GraalVM for JDK, carrying a CVSS 3.1 score of 8.1 High.

What makes Java4Shell stand out is not a 9.8 score on paper, but its reach. All 11 vulnerabilities patched in Oracle Java SE this month are remotely exploitable over a network without authentication. Affected releases span virtually every active enterprise Java branch: Java SE 8u511b33, 11.0.33.0.3, 17.0.21.0.3, 21.0.13.0.3, 25.0.5.0.3, and 27.0.1.0.3, along with GraalVM for JDK 17.0.21.0.3 and 21.0.13.0.3.

Tenable notes that deeper technical details on Java4Shell are expected to surface soon, which usually means proof-of-concept analysis and automated scanning signatures follow closely behind. Organizations running internet-facing Java application servers, API gateways, or build runners should inventory JDK versions now rather than waiting for public exploit write-ups to circulate.

In a recent development, even internal microservices deserve a quick check, because compiler-level flaws in shared JVM runtimes often surface inside container base images that developers pull without thinking about underlying patch levels. Updating base JDK images in CI/CD registries early prevents downstream teams from shipping newly built services on top of vulnerable November 2026 runtimes.

While Java4Shell grabs attention, the highest raw CVSS scores in Oracle's November 2026 advisory hit core database and web-tier components:.

Industry observers note that first, Oracle APEX (versions 24.1.22, 24.2.21, 26.1.5, and 26.2.0) and Oracle REST Data Services (ORDS) (versions 24.2.0 through 26.3.0) share CVE-2026-114849, a CVSS 9.8 Critical HTTPS vulnerability remotely exploitable without authentication (AV:N/AC:L/PR:N/UI:N). APEX picks up a second 9.8 Critical unauthenticated HTTPS flaw in CVE-2026-114850, while ORDS also patches CVE-2026-114856 at 9.6 Critical (network-exploitable without credentials, requiring only user interaction). Because ORDS and APEX frequently sit directly behind corporate reverse proxies or web application firewalls, leaving them unpatched exposes database-backed web apps to high-impact compromise.

It has been revealed that second, Oracle Database Server (versions 19.3 to 19.33, 21.3 to 21.24, and 23.4.0 to 23.26.4) patches three CVSS 9.9 Critical vulnerabilities in Oracle Text and RDBMS: CVE-2026-114819, CVE-2026-114848, and CVE-2026-114822. These require a Create Session privilege over Oracle Net, meaning an authenticated database user or compromised service account can abuse them to cross security boundaries (Scope: Changed) with High confidentiality, integrity, and availability impact.

Third, Oracle Autonomous Health Framework (versions 26.4 to 26.10) receives a CVSS 9.1 Critical fix for CVE-2026-114847 in its developer triaging platform over HTTP, alongside CVE-2026-19445 (8.1 High in Python TLS handling) and CVE-2026-102274 (7.5 High in PyJWT).

Oracle's November 2026 advisory also includes an important reminder for teams running automated vulnerability scanners: VEX (Vulnerability Exploitability eXchange) justifications are embedded directly below product risk matrices.

According to recent reports, for example, Oracle ships third-party library updates for OpenSSL (CVE-2026-72897, CVSS 7.5), Python (CVE-2026-115557, CVSS 7.4), jackson-core (CVE-2026-89425, CVSS 6.5), and Apache HttpClient (CVE-2026-64607, CVSS 4.3) in Database Server. At the same time, Oracle marks several third-party CVEs in Apache MINA SSHD, DBI, jline, and jsoup as non-exploitable in context (vulnerable_code_not_in_execute_path or vulnerable_code_cannot_be_controlled_by_adversary). Reviewing those VEX tags prevents engineering teams from burning sprint cycles chasing false positives in software composition analysis reports.

According to recent reports, oracle also explicitly warns customers not to overlook four standalone October 2026 Security Alerts issued ahead of this CSPU: CVE-2026-91403 (October 21), CVE-2026-114820 (October 24), and CVE-2026-109618 / CVE-2026-109619 (October 25). If your patching pipeline skipped those out-of-band October alerts, fold them into this week's change window alongside the November 17 CSPU.

Sources indicate that in addition, Oracle reminds administrators that protocol entries in its risk matrices cover secure variants automatically. When HTTP is listed as an affected protocol in an Oracle Fusion Middleware, APEX, or ORDS matrix, HTTPS endpoints are affected as well unless Oracle explicitly notes otherwise.

It has been revealed that trying to patch 655 problems simultaneously across ERP, middleware, and database tiers usually stalls change boards. A tiered rollout focuses effort where unauthenticated attackers have the shortest path:.

Recent findings suggest that if your organization still relies on legacy Oracle releases outside Premier Support or Extended Support, remember that Oracle does not test or issue CSPU patches for unsupported branches even when the underlying code remains vulnerable. Use this November cycle to audit end-of-support versions across MySQL 8.0, older WebLogic domains, and unpatched Java runtimes before December 15 arrives.

Oracle's Critical Patch Updates (CPUs) are full quarterly cumulative releases, whereas Critical Security Patch Updates (CSPUs), introduced in May 2026, ship monthly on the third Tuesday to deliver focused, high-priority fixes between quarterly cycles.
