Teams that add an obfuscation step to their release usually discover a code-review problem within a week: someone commits a protected bundle, the pull request shows a 40,000-line diff of unreadable characters, and reviewers either rubber-stamp it or give up. Here is a cleaner arrangement.

Protected output is a build artifact. Treat it like minified bundles: generate it in CI, store it as a release artifact, and keep it out of the repository. Then the only thing a pull request can change about protection is the configuration.

Put the options you send to the protection step in one file, for example protect.config.json. For MeowShield's authorized API the documented request has sourceCode, apiToken and an options object whose mode is low, medium or high. The token comes from a CI secret, never from the file. Copy the full current options shape from the official API docs rather than from memory.
