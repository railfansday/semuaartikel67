tl;dr — I recommend using llama-cpp-rdna-boosts if you have an AMD graphics card. It’s lean, and increased my token generation from 35 to 55 tokens/second, and my prefill from 700 to 1300 tokens per second. YMMV.

As of November 2026, an explosion in the number of bespoke inference engines has taken place. Many of them take inspiration from the engines that enabled much of the LLM inference up 'til now: llama.cpp, SGLang, vLLM, etc.

Industry observers note that the rationale isn’t that those options are bad, but merely that they are generalist engines, optimized for no particular hardware and with a focus on broad compatibility. Others feel the development pace of those engines have slowed down, and with the help of LLMs, they can move faster on their own.

Some examples of these new inference engines* are Strata, Basalt, RustingStrata, etc….

These fresh forks generally all have a few things in common:.

Sources indicate that … and the results are stunning! Strata is able to run a heavily-quantized model of Qwen 3.8 Flash Next, a 180B parameter model, on a 16GB VRAM graphics card, and 16GB system RAM, and have it generate tokens at a surprisingly high rate.

In and of itself those three things are not red flags (the second is concerning, of course, but it may be SOP in a year’s time — who knows!), but as these projects have evolved, that relentless chase toward higher token generation speeds has taken an unfortunate turn, in that the optimizations are less about hardware-specific changes, but more about changing how the model thinks so that it goes brrr faster.

In a recent development, strata specifically has taken to preferring to poll experts loaded in VRAM even if other experts (pushed to system RAM/disk) would have been normally chosen. This is just one example, but certainly not the last.

That noted, I was fortunate to stumble upon yet another project that promised improvements, delivered, and was more aligned with my software development philosophy.

Industry observers note that enter llama-cpp-rdna-boosts. It is a repository that contains a minimal set of changes that you apply against a pinned commit of llama.cpp. It is in essence a fork, but one whose changeset is continually re-applied to newer versions of llama.cpp. It contains AMD-specific improvements that drastically improve prefill and token-generation speeds.

Recent findings suggest that if you have ROCm libraries installed on your system, you can build the image yourself. I didn’t want to mess with that, so I used the pre-built images published.

podman pull ghcr.io/stew675/llama-cpp-rdna-boosts:server-rocm-10.1.

This sets up an image that you can run sandboxed via podman to launch the inference server:.

On my setup, an AMD R9700 connected to my laptop via an eGPU interface, this improved prefill and token generation rates when running ukisai/Swift-1.5-Qwen3.8-27B-GGUF (Q6_K_L) with MTP enabled:.

Strata and its ilk were always promising the moon and it was never clear what steps they took to make that happen. I’m very much looking forward to what the rdna-boosts community come up with next.

Industry observers note that * It’s worth noting that between these two groups, vllm-radiance made an appearance, which was a fork of vLLM with AMD-specific patches. I tried this too, but the build steps were so onerous and vLLM so overbuilt for my specific use case (1 machine, 1 developer), that I abandoned it and went back to vanilla llama.cpp.
