Microsoft suggests Registry hack to work around hotpatch woes

In a recent development, app problems in Windows after default hotpatching? Who could have foreseen that?

Some Windows 11 applications might fail to install or launch after Microsoft's November hotpatch, but not to worry: there's a Registry tweak to work around it.

Microsoft has confirmed it isn't administrators' imaginations. The November hotpatch is causing application errors, including in little-used and obscure apps such as Outlook.

According to recent reports, affected applications may fail during installation, launch, or use, displaying errors such as "ERROR_ALLOTTED_SPACE_EXCEEDED (0xC0000099)." Microsoft's investigation points to applications that load the 32-bit Windows Installer DLL, msi.dll. The problem is more common with 32-bit software, but can also affect 64-bit applications "under certain circumstances.".

The workaround involves fiddling with the Registry on affected devices, so is not for the faint of heart and a backup is a good idea before diving in. Microsoft claims the key "HotPatchTableSize" in the folder "HKLM\SYSTEM\CurrentControlSet\Control\Session Manager\Memory Management" needs to be set to "2000" followed by a restart.

Just the thing to round out the week for administrators.

It has been revealed that the glitch affects the November hotpatch, not the standard monthly cumulative security update. "Devices which installed the November 2026 Windows monthly security update are not expected to be affected by this issue," Microsoft said.

According to recent reports, windows hotpatches are security updates that don't require a device restart (unless, as in this instance, administrators have to do so to address errors after a hotpatch is installed). Windows 11 hotpatching requires version 24H2 or later, an eligible subscription, and the necessary management and security configuration.

"Hotpatch upgrade package size is significantly smaller than the standard cumulative updates," Microsoft remarked, and the goal is to "streamline the installation process and enhance compliance efficiency.".

The offending hotpatch, KB5132043, was released on November 10. It followed the October 13 baseline, which was a prerequisite.

Industry observers note that microsoft made hotpatching the default in Windows Autopatch earlier this year. At the time, we asked: "What could possibly go wrong?".

Thanks to November's hotpatch, we have our answer. ®.
