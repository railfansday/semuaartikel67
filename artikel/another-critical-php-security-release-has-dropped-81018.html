📑 Quick Jump: 1. Overview • 2. Key Details • 3. Closing Notes

At least one dangerous RCE bug got a fix on Thursday.

Industry observers note that apologies in advance to all patch managers and security teams that thought they might get a break this week. The PHP Foundation has released several more patches, covering all supported versions, and including at least one rated “critical.”.

These fortunately were not leaked leaked like last month’s critical PHP2Shell flaws – but a Wednesday advisory warned, “The issues rated critical require either non-default configuration or uncommon setups,” urging PHP users to “prepare to upgrade promptly once the releases become available.”.

One of the vulnerabilities is another remote code execution (RCE) flaw, tracked as CVE-2026-115560.

In October, the PHP Foundation told The Register that it had reserved this CVE identifier for another RCE bug, but added it would not get an emergency fix like the earlier two PHP2Shell vulnerabilities because the third one doesn't pose the same risk.

Recent findings suggest that CVE-2026-115560 “requires a very unlikely combination of configuration and specific PHP application code, which we do not expect to occur in practical use of PHP,” Elizabeth Barron, executive director of the PHP Foundation, told The Register at the time. “The matter can be mitigated with a configuration setting. So for the moment the PHP Security Team has only published an informational advisory on the PHP website, explaining exactly this situation.”.

The earlier informational advisory urged customers to “set session.upload_progress.enabled=0 until the next regular bugfix release, to fully protect from an unlikely RCE vector.”.

These unlikely RCE attacks require an application to set “session.serialize_handler to php_binary or php_serialize in its configuration and then switch it to php at runtime with ini_set() before calling session_start().”.

Additionally, the session upload progress feature must be enabled, which the PHP Foundation said is very unlikely in real-world applications.

Recent findings suggest that overall, a large number of bugs were fixed and CVEs patched across five releases. Get more info on the PHP news page here.

The November security releases follow a hectic October emergency PHP patch-a-thon, with security teams racing to apply fixes for CVE-2026-109618 and CVE-2026-109619, collectively called PHP2Shell, before attackers could abuse the memory-safety flaws in the open source programming language running on about 70 percent of websites.

While it took miscreants longer to reverse engineer the PHP2Shell fixes than some researchers had anticipated – and the entire internet didn’t burn down in the meantime – the US Cybersecurity and Infrastructure Security Agency (CISA) did add the two PHP vulns to its Known Exploited Vulnerabilities catalog on October 26.

Suspected Chinese attackers chained PHP2Shell with a Linux kernel privilege-escalation exploit to root 25 servers, including Palo Alto Networks firewalls linked to US government-affiliated organizations, as early as October 23, according to Dream researchers.

Sources indicate that the Israeli AI cybersecurity startup mentioned the attackers targeted organizations across the US, Japan, Taiwan, and South Korea, and “likely still” have persistent, remote access to compromised organizations’ networks. ®.
