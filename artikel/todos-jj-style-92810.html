I love using JJ and recently I’ve found a cool way to handle TODOs that works for me.

Usually I’ll put them in a TODO.md file which is pretty standard. But, I forget about this file quickly and am not very good at remembering to cross stuff off. Also since it’s in-tree I’ll often not want to update it, and then forget to do so later.

It has been revealed that JJ has a cool feature where you can make empty changes, and even write descriptions for them before actually doing work. So what if I just make all the stuff I wanna do later as empty commits?

In a recent development, pretty nice! When I want to start working on something I’ll rebase it out of my TODO tree and onto some other change.

I need to rebase my “TODO base” forward when i make changes, but because it’s empty it will never have conflicts and can pretty easily move around.

TODOs that depend on other TODOs also naturally fit here, I just make fresh empty commits on top of other empty commits.

According to recent reports, I have git.private-commits configured to make sure nothing with the private: prefix will get pushed. This ensures my TODOs stay on my local system. Of course, there are benefits to not doing this.

Anyway that’s about it, not very ground breaking but something I like.
