Ledger, a crypto wallet firm, mentioned it had experienced a security incident related to Optimizely, a third-party service used on its official website, but reassured its users about the security of their devices and private keys.

In a post, Ledger remarked it was aware of a security incident impacting Optimizely, a third-party service provider used by many other sites as well.

We are aware of a security incident affecting Optimizely, a third-party service used on https://t.co/d2pWxdG49X, alongside numerous other websites. Our team has remediated the problem, and the malicious code is no longer being served through our website. This incident does not affect the security architecture of Ledger devices. Your private keys remain protected by your Ledger device. For more information from Optimizely: https://t.co/CxzmBxYadb.

Website optimization platform Optimizely stated it had discovered and contained a security incident affecting some of its Web Experimentation customers on November 16, 2026. Optimizely stated that the vulnerable path has now been blocked, the injected code has been removed, and customers have been contacted directly.

Along these lines, Ledger confirmed that its team had remediated the issue and that the malicious code was no longer being served through its website.

Ledger emphasizes that the incident did not affect the security architecture of Ledger devices and that user private keys remain protected by their Ledger device, thus reassuring customers that the incident had not compromised the core security of its wallet products.

Sources indicate that according to researcher Scott Helme, on November 16, 2026, malicious JavaScript was served to visitors of 178 organizations' websites across several sectors through the Optimizely Web Experimentation platform. The websites included Zoom, the BBC, CNN, Salesforce, GitLab, IKEA, HSBC, Equifax, Air France-KLM, Ledger, and Peacock.

Most of the malicious code has now been removed, with only 1 of the 188 infected snippets found, down from 169.

Industry observers note that the main point is that trusted JavaScript is not always trustworthy. A third-party dependency can exploit a website without ever breaking the website's own code or infrastructure.
