An AI coding agent for DOS. It runs on an IBM PC XT: an 8088 at 4.77 MHz, 640K of RAM, a CGA card.

Backstory: The IBM PC was my first computer. Rather, it was my parents’ first personal computer that I got to use at a very early age.

It was already obsolete by the time I was old enough to use it, but at 5 years old it was a magical device that I could make do different things depending on what I typed.

I learned how to type and use DOS so that I could launch some early “Learn the Alphabet” games that my mom had bought me. I learned some elementary-level use of BASIC, but at the time that didn’t progress much further than making some number guessing games and other small projects.

Sources indicate that from there, many years passed but I still have some of the original parts of that PC. I have a collection of vintage machines that mean something to me, with my fully maxed-out IBM PC 5160 being the centerpiece of my collection. It still has a working 20 MB hard drive, but that’s disconnected in favor of a PicoMEM that lets me emulate a hard drive off of an SD card, making experimentation and play much easier.

Industry observers note that old, meet upcoming. New, meet old: I love intersections of old and new technology. What better way to cross the two than building an AI coding agent to run on DOS on original hardware?

And of course, what better to build it than an AI coding agent?

I (read: Claude) built this for my own entertainment. I wanted to see how far I could push an AI coding agent to build something given out of the (modern) norm of constraints. Also, can that something it built then build other somethings? 100% of this repo is written by Claude, with the exception of the text within this box.

As explained in more detail below, the harness runs on the native OS and hardware and relies on a “bridge” PC in order to handle TLS, which would’ve been more than what an 8088 could handle.

Type CLAWDOS at the C:\> prompt and talk to Claude. It reads and edits the files on your disk, writes programs, compiles them with Turbo C, runs them and looks at what they draw on the screen. It keeps notes between conversations and picks up where it left off.

The whole harness runs on the PC. HARNESS.EXE is a 176 KB DOS program that speaks the Claude Messages API itself: it writes the requests, parses the streamed reply, runs the tools and keeps every conversation on its own disk. The 8088 does everything but TLS.

Every screen below comes from a 5160 at 4.77 MHz, emulated in 86Box. The conversations are with the live API.

One message: “Write PRIMES.C: print the primes below 100. Compile it with Turbo C and run it.” ClawDOS reads its guide to the compilers on this machine, writes the source, then compiles, links and runs it in a single tool call. The answer is on the screen 64 seconds after Enter, 26 of them spent compiling, linking and running.

In a recent development, the compiler gets the machine to itself. For a build, ClawDOS saves its state and leaves memory, Turbo C runs with about 450K free, and the harness comes back on the same conversation with the program’s output in hand.

Recent findings suggest that clawDOS wrote this tribute to the 1983 film on the PC itself: a vector world map, missiles arcing over the pole, a tic-tac-toe endgame, and a score for the PC speaker or an AdLib card. Five files of Turbo C, 15 KB of source, a WG.EXE under 10 KB.

It has been revealed that asked to make the demo exit on its own, ClawDOS goes looking. It searches the sources for the keyboard wait, reads the file, says what it found and edits one line. Each tool call shows in the transcript with its result, and between them Claude says what it is about to do.

Text art in sixteen colours, straight into the transcript, and music on the PC speaker in GW-BASIC’s PLAY language.

According to recent reports, A chat screen built for the CGA. Replies stream onto the screen as they arrive, word-wrapped at 80 columns in code page 437. Writes are timed to the retrace, so there is no snow. The transcript scrolls in hardware through the CRTC start address, with PgUp and PgDn to go back. The spinner and its seconds run from the timer interrupt and keep moving while the PC is busy.

A development kit on the disk. Two assemblers (TINYASM and WASM), Bruce’s C, GW-BASIC and the lDebug debugger, plus Turbo C 2.0, installed from your own floppy images in external/. All of them are proven on the 8088, and ClawDOS knows how to drive each one.

In a recent development, memories and skills. Memories are what ClawDOS learns on your PC: what you built together, what worked, what you like. Skills are guides that ship with it, such as the dev tools and CGA demo effects. Both are plain text files on the disk, listed in every conversation’s system prompt and read when they fit the task. F4 browses the memories:.

Sources indicate that safe mode. On by default. Anything that changes a file, memory or a port asks Allow ...? (y/n) first. F3 turns it off.

Conversations that last. Every chat is a file on the disk in the API’s own message format. F6 lists them, Enter reopens one, and your next message carries it on. A chat cut off by the power switch reopens too.

In a recent development, any model, mid-conversation. /model lists the providers in CLAWDOS.CFG and switches between them and their models without losing the conversation. F5 sets how hard Claude thinks, from low to max. Any host that speaks the Messages API works.

Industry observers note that easy on a slow link. The system prompt and tools are cached by the API. After a conversation’s first request the PC uploads only what is newly introduced, so a tool result goes up in about 500 bytes. A dropped connection or an overloaded API is retried, and the turn carries on.

A flight recorder. CLAWDOS.LOG has a line for every round: time to first token, upload size and time, tokens in and out, cache reads.

docs/API.md has exactly what ClawDOS sends and what it expects back.

You need a Mac or a Windows PC with Python 3, and an Anthropic API key. On Windows the command is python.

At the C:\> prompt, type CLAWDOS.

According to recent reports, no key? python3 tunnel/mockapi.py plays the API offline: type CLAWDOS 10.0.2.2:18023 and send !help.

On a real PC: build with the address of the machine running the tunnel (python3 scripts/build.py --tunnel 192.168.1.10:8443), copy CLAWDOS.IMG to the PicoMEM’s microSD card, pick it as the hard disk in the PicoMEM’s menu, boot, and type CLAWDOS. Later builds update the card’s image in place and keep its memories and chats (python3 scripts/build.py --update /path/to/CLAWDOS.IMG).

/model, /chats, /memories, /latest and /quit work from the input box. CLAWDOS -m "..." sends a message from the command line and -c NAME reopens a chat.

Sources indicate that clawDOS is free software under the GNU General Public License, version 3 or (at your option) any later version: see LICENSE. HARNESS.EXE links mTCP, which is GPLv3. The FreeDOS boot sector in src/boot/freedos is vendored unmodified under its own GPLv2-or-later license (its COPYING). ClawDOS stands on mTCP, FreeDOS, Open Watcom, the PicoMEM, 86Box and DOSBox-X.
