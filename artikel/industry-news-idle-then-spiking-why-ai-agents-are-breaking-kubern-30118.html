Industry News: Idle, then spiking: Why AI agents are breaking Kubernetes resource planning

UPDATED 15:35 EST / NOVEMBER 17 2026.

AI agents are changing the economics of cloud infrastructure, and autonomous orchestration is becoming the way platform teams keep up. Agentic workloads sit idle and then spike without warning. That pattern leaves static resource settings either wasteful or likely to fail.

Container orchestration for AI is fast becoming the backbone of production AI, and agents are adding a new layer of strain. Compute costs are climbing and reliability problems are harder to contain because everything an agent does ultimately runs on CPU and memory, according to Yodar Shafrir (pictured), founder and chief executive officer of ScaleOps Inc.

“Agents and all the agent workloads pretty much made everything way more complex when managing infrastructure,” Shafrir mentioned. “Eventually, all the complexity that existed before just got much worse. Today, the compute cost has grown dramatically. Everything that agents execute eventually runs on compute.”.

Sources indicate that shafrir spoke with theCUBE Research’s Paul Nashawaty and Rebecca Knight at KubeCon + CloudNativeCon NA, during an exclusive broadcast on theCUBE, SiliconANGLE Media’s livestreaming studio. They discussed how autonomous orchestration lets ScaleOps adjust resources in real time as AI agents spike, cutting both costs and crashes. (* Disclosure below.).

Agents behave differently from traditional microservices. An agent waits for a human or another agent, checks with a large language model and then runs its task in a burst. Teams must provision for the highest spike while the agent holds its memory the whole time, Shafrir explained. When resources fall short, a crashed step has to rerun and burns tokens all over again.

“We actually see that agents crash due to not having enough resources 80% more often compared with traditional microservices,” Shafrir said. “The reliability is much harder to manage.”.

For ScaleOps, the answer is to make resource decisions in real time. It adjusts allocations, replicas and node placement for every application, agent and Model Context Protocol server, which the company states cuts cloud costs by 70% to 80%. Customers such as Adobe Inc. and Salesforce Inc. build trust by first running the platform in read-only mode on their hardest environments, according to Shafrir.

“We understand for every application: What is it connected to? What does it communicate with? What is the business state of every application?” Shafrir mentioned. “We learn from historical patterns.”.

Sources indicate that scaleOps has also added a capability that lets other workloads use an agent’s resources while it sits idle. It also uses memory swap so an agent gets memory only when it needs it. The firm claims this makes running agents 90% more cost-efficient without moving off Kubernetes. Given the cost of always-on agents, Shafrir sees autonomous orchestration as the only workable model.

“We are now in a phase where humans and all the traditional scaling capabilities that existed in the past are pretty much irrelevant for today’s world because they’re too static and they require a human to go and configure them,” Shafrir remarked. “When things are so dynamic, it no longer works the same way.”.
