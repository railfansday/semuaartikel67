📑 Quick Jump: 1. Overview • 2. Key Details • 3. Closing Notes

A model can reason about a task. Completing that task takes more: the right context, tools, execution environment, and controls, and an agent loop that brings them together.

Microsoft’s unified harness strategy brings a shared execution foundation across our agent experiences while preserving customer choice. In Microsoft Foundry, that means you can choose a supported model and decide how much of the agent stack to build yourself, without having to assemble every layer around it.

In a recent development, today, we’re introducing the Microsoft Copilot harness in Foundry Agent Service in public preview. It gives developers a fully managed way to build agents that reason, use tools, and complete complex, long-running tasks. It’s our opinionated approach to helping agents complete complex work. We’re also announcing general availability of long-running resilience for hosted agents. Together, these capabilities help developers build more reliable agents for complex, long-running workflows.

Many teams building agents end up implementing the same execution machinery: coordinating model and tool calls, maintaining working context, managing files, and deciding how to continue when a task requires more than one step. That work matters, but it isn’t usually what differentiates your application.

The Copilot harness gives you a managed execution system for agents you define declaratively in Foundry Agent Service. Microsoft runs the agent loop and sandbox; you bring the knowledge, procedures, and tools that make the agent yours.

In a recent development, the harness manages working context as tasks develop and coordinates model and tool steps toward a requested outcome, within configured limits and policy boundaries. You choose a supported Foundry model without having to rewrite the orchestration around it.

That lets your team focus on improving the agent’s expertise and evaluating its results.

Industry observers note that azd is one authoring option. You can also start in the Foundry portal or use Foundry Toolkit for Visual Studio Code. In the GitHub Copilot app, the Microsoft Foundry plugin and Microsoft Foundry Skill provide a conversational path to creating and managing prompt agents.

Industry observers note that these options let you build on a managed harness. When your application needs a different framework or its own execution logic, hosted agents give you another path.

In a recent development, hosted agents in Foundry Agent Service let you bring your own framework, agent loop, middleware, dependencies, and runtime behavior while Foundry manages hosting. Long-running resilience for hosted agents is generally available this week, helping agents recover from interruptions during work that takes hours or days.

It has been revealed that foundry detects interruptions and restarts the work with its original input. Your code saves progress and intermediate results so the agent can pick up where it left off. If the agent updates another system, your workflow also needs to prevent duplicate actions when work restarts.

For example, an agent analyzing a large dataset can save completed stages and resume from the last checkpoint. If it also creates a report in another system, it should check whether the report already exists before creating it again.

Industry observers note that foundry provides the recovery foundation; your application determines what to save and how to resume. Conversation history alone isn’t enough to restore work in progress.

These workflows have different requirements, and there isn’t one right level of abstraction for every agent. Foundry Agent Service lets you choose where to invest your engineering effort:.

Start with the level that fits your application’s requirements, rather than taking ownership of infrastructure you don’t need to differentiate.

In a recent development, during this preview, select the Microsoft Copilot harness when creating the agent. Existing agents are unchanged, switching the harness after creation isn’t supported yet, and Foundry manages the execution environment’s CPU, memory, and idle settings.

You can start in the Microsoft Foundry portal or use azd to keep the agent definition alongside the rest of your application.

Industry observers note that pricing: Billing for the Copilot harness in Foundry Agent Service begins December 1, 2026, with consumption-based pricing. Harness runtime usage is free before December 1; model inference and separately billed tools and connected services remain subject to their applicable charges. Starting December 1, sandbox compute and memory are billed at USD $0.0994 per vCPU-hour and $0.0118 per GiB-hour, respectively. Prices may vary by region and agreement.
