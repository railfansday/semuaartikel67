Recent findings suggest that running an AI agent on your own GPU sounds simple: point it at Ollama and stop paying per token. I set up OpenClaw, an open-source AI assistant, with a 9B model in Ollama on one RTX 3090 and connected it to Discord. Then I read the Ollama log for every request.

The agent worked. The numbers were not what I expected, though. A one-line question turned into a prompt of more than 18,000 tokens, the first reply took over a minute, and the small model sometimes guessed instead of using its tools.

This article covers what I measured and what each number means if you plan to run an agent on local hardware.

OpenClaw ran in Docker and reached Ollama on the host at http://host.docker.internal:11434. Discord was the chat interface, and OpenClaw's web panel showed the sessions and context use.

Recent findings suggest that this article is about the results, not the installation. The full step-by-step setup is in a separate guide to running OpenClaw in Docker with Ollama and Discord. That guide covers the Compose file, the Discord bot and how to keep the ports off your network.

All timings below come from the Ollama log on the test machine. Ollama loaded the model with a 32,768-token context.

My first message in Discord was short: "Which model are you running on, and what is 17 * 23?" The bot answered correctly: it ran on ollama/qwen3.5:9b, and 17 × 23 is 391.

Sources indicate that the speed-up comes from prompt caching. The system prompt, tool definitions and workspace files at the start of the prompt stay the same between requests. Ollama kept that part cached and processed only the upcoming tokens. The model wrote at 91 to 96 tokens per second in every test.

In a recent development, ollama's documentation says models stay in memory for 5 minutes by default before they are unloaded. After that, the next message pays the load time again. You can change this with the OLLAMA_KEEP_ALIVE environment variable on the Ollama server, or with the keep_alive parameter per request. A negative value, such as -1, keeps the model loaded. I did not change this setting in the test.

If you run Ollama in Docker, pass the variable with -e OLLAMA_KEEP_ALIVE=-1 or in the environment: section of your Compose file.

Two things used the GPU besides my chat messages.

It has been revealed that A heartbeat. OpenClaw's web panel listed one scheduled automation, heartbeat-main, which runs every 30 minutes. The agent wakes on that schedule, so the model gets called even when nobody chats. With Ollama's 5-minute default, the model is unloaded between heartbeats unless someone chatted recently, so a heartbeat most likely starts with a model load. I did not measure this.

Sources indicate that an embedding model. During the first message, OpenClaw also called Ollama's /api/embed endpoint twice to index its memory. It used qwen3-embedding:4b, which was already installed on the Ollama server. I did not set OpenClaw to use that model; it picked it on its own.
