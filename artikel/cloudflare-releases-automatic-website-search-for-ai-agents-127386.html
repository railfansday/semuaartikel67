Cloudflare Releases Automatic Website Search for AI Agents

📑 Quick Jump: 1. Overview • 2. Key Details • 3. Closing Notes

Cloudflare launched Search for Agents on November 25, 2026, making the beta feature available on every initiative, including Free. A dashboard toggle or API control now automates website indexing and exposes an API that AI agents can discover under the site’s own domain.

In a recent development, previously, customers had to manually create and configure an AI Search instance, integrate its search endpoints with their domain and tell agents where to find the index. For a domain already onboarded to Cloudflare, activation creates the instance and starts crawling and indexing; once indexed, content is searchable at /.well-known/search. The setup documentation instructs customers to index only content they intend to make publicly searchable.

It has been revealed that cloudflare advertises the endpoint on every page. HTML responses carry metadata in their containing agent instructions, the endpoint, the GET method and a documentation link. Sites that also enable Markdown for Agents provide equivalent YAML front matter to agents requesting Markdown. An agent can therefore discover the search capability from a page instead of needing prior knowledge of the site’s index.

Industry observers note that agents submit keywords or natural-language questions through the GET q parameter. Responses contain retrieved Markdown with source references and relevance scores, not an answer generated by another model. Cloudflare’s design leaves synthesis with the agent’s own model and user conversation, so the website supplies source material rather than taking over the response.

Sources indicate that cloudflare’s OpenCode demonstration highlighted an agent discovering the endpoint on the company’s developer-documentation homepage, asking about Cloudflare Artifacts and returning a correct answer a few seconds later. Access remains subject to the domain’s bot-management, AI Crawl Control and Web Application Firewall settings, so the discovery metadata does not bypass existing security controls.

It has been revealed that new instances use Discover crawling, which finds pages through sitemaps and links without requiring a sitemap. The defaults crawl five link hops deep, synchronize every 24 hours and exclude subdomains. Search combines vector and keyword retrieval using the @cf/qwen/qwen3-embedding-0.6b embedding model, returns up to 10 chunks and starts with reranking and query rewriting disabled. Similarity caching is enabled for 48 hours.

The embedding model and data source are fixed when the instance is created, though other configurable settings can be changed later. Because the feature uses a standard AI Search instance, owners can also enable public REST or MCP endpoints, access it through a Workers binding or embed search components for human visitors. Those additions are separate and are not required for agent search.

According to recent reports, alongside GET, the endpoint accepts HTTP QUERY requests containing either UTF-8 plain text or a JSON object with a q field. RFC 10008, published in June 2026 and coauthored by Cloudflare’s James M. Snell, defines QUERY as a safe, idempotent way to put query criteria in a request body. Unlike POST, it can be automatically retried without concern for partial state changes, and its responses are cacheable.

It has been revealed that usage is metered across content ingestion, index storage and queries. AI Search billing begins December 1, 2026, and the limits and pricing documentation lists monthly account allowances of 5 million ingestion tokens, 10 GB-month of storage, 1,000 semantic queries and 1,000 full-text queries. Overage rates are $0.75 per million base-ingestion tokens, $2.00 per GB-month of storage, $0.75 per 1,000 semantic, vector or hybrid queries, and $0.10 per 1,000 full-text queries.

Crawl allowances add another constraint. Discover crawling accepts up to 100,000 pages, but per-instance file limits and daily crawl ceilings also apply; the lowest applicable limit determines the resulting page count. On Workers Free, the daily ceiling is 500 pages, making it the binding constraint despite the larger crawl allowance.

The launch makes website retrieval part of Cloudflare’s network configuration instead of a custom integration. Its practical value depends on agents acting on the discovery metadata and on site owners aligning public-content, access and crawl settings. Those choices determine how much useful material an agent can retrieve without crawling pages individually.
